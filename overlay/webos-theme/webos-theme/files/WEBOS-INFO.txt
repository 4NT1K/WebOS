WebOS 1.021 "Ashen" — system information
========================================

Everything important about this installed system, in one file.
Installed copy: /usr/share/webos/WEBOS-INFO.txt
Repo copy:      overlay/webos-theme/webos-theme/files/WEBOS-INFO.txt

RELEASE / IDENTITY
------------------
- Version      : WebOS 1.021 "Ashen"
- Base         : Gentoo Linux, OpenRC + elogind (no systemd)
- Kernel       : sys-kernel/webos-kernel 6.12 LTS, localversion "-webos"
- Architecture : amd64, 64-bit only (ABI_X86="64", no multilib)
- Desktops     : Hyprland (default), Noctalia shell, KDE Plasma 6 (Wayland)
- Installer    : webos-installer (Rust TUI + optional egui GUI)
- Filesystems  : btrfs (default, subvolumes + zstd), ext4, xfs; optional LUKS2
- Bootloader   : GRUB2 (BIOS and UEFI)
- ISO          : webos-1.021-Ashen-amd64.iso (split parts + SHA256SUMS.txt)
- Source       : https://github.com/4NT1K/WebOS
- Release file : /etc/os-release and /etc/webos-release both report 1.021

QUICK START
-----------
1. Boot the ISO (Ventoy, Rufus, balenaEtcher or dd). The live menu appears on
   tty1: 1) install, 2) root shell, 3) inspect hardware.
2. Installer: choose disk, filesystem, swap, profile, dotfiles profile,
   account, timezone/locale/keymap, then confirm the summary.
3. Reboot, remove the medium, log in at SDDM (or the console for Minimal).
4. First login applies the rice; waybar, wallpaper, notifications, portals and
   the polkit agent start automatically.
5. Update with `sudo webos-update`.

WHAT WAS FIXED IN 1.021
-----------------------
This is a fix release for the issues reported against 1.02:
- Hyprland loaded the stock ~/.config/hypr/hyprland.lua instead of the WebOS
  hyprland.conf, silently disabling autostart. webos-session now moves any
  lua to hyprland.lua.webos-disabled and launches
  `Hyprland -c ~/.config/hypr/hyprland.conf` explicitly.
- polkitd could not be D-Bus activated: an ownership pass had stripped setuid
  from /usr/libexec/dbus-daemon-launch-helper. It is now 4754 root:messagebus
  in the rootfs, live image and installer, and ownership normalisation no
  longer chowns root-owned files.
- fastfetch failed with "Image logo types are not supported" (built without
  ImageMagick/chafa). The shipped config uses the text cobweb logo
  (`logo.type = file`, webos.txt), which renders everywhere.
- fastfetch now appears in every interactive shell: bash, zsh and fish hooks
  are installed, foot uses webos-shell like kitty, and WEBOS_FASTFETCH_SHOWN
  prevents duplicate cards.
- The TUI installer progress bar lost its "%" sign, mixed a thin track with a
  thick fill, drifted out of its panel and ran past the border. It is now a
  custom two-line widget: percentage/phase on one line, a full-width track of
  filled/empty cells below, sized from the panel's real inner width.
- /home/*/.local/state/webos/rice.manifest was root-owned and unreadable.
  webos-rice and webos-dotfiles now return state/config files to the home
  directory owner; `webos-rice --doctor` no longer uses an unset ${home}.
- Duplicate/stale SDDM entries: webos.desktop is no longer installed into
  /usr/share/xsessions (Hyprland is Wayland-only). The installer points SDDM
  at /usr/share/webos/sessions and links only the chosen session.
- Non-Noctalia installs no longer ship or start Noctalia. The Hyprland,
  Plasma and Minimal profiles unmerge gui-apps/noctalia and remove its session
  entry and seeded config. "mono" only restyles waybar/kitty/mako.
- /etc/webos-release was hard-coded to "1.01 (Ashen)" and written twice. It
  now derives the version from the installed /etc/os-release.
- Same-version rebuilds could keep a stale installer/theme. The rootfs stage
  now unmerges and rebuilds app-admin/webos-installer and webos-theme.
- `webos-rice --doctor` no longer fails the Inter/JetBrains Mono checks when
  fc-list is unavailable, and no longer fails "greetd configured" on healthy
  SDDM systems.

EXPECTED BEHAVIOUR
------------------
Boot / live medium
- The banner reads "WebOS 1.021 (Ashen) — live medium".
- Nothing is written to disk until the summary is confirmed.
- The installer progress panel stays inside its border, keeps the "%" sign,
  and shows one consistent bar: red 0-25%, light red/orange 26-50%, yellow
  51-75%, light green 76-100%. ANSI colours survive the Linux console.

SDDM / sessions
- Exactly ONE graphical session is offered, the one chosen at install:
  Full -> "WebOS", Noctalia -> "WebOS Noctalia", Plasma -> "Plasma (Wayland)",
  Minimal -> no display manager (TTY login).
- Plasma is Wayland-only; there is no Plasma X11 entry.
- A non-Noctalia install has no noctalia binary, session entry or
  ~/.config/noctalia.

Hyprland (all rice profiles)
- waybar appears, wallpaper is set, mako shows notifications, hypridle runs,
  hyprpaper keeps the wallpaper, and portals + a polkit agent are active.
- Super+Return opens kitty with the WebOS fastfetch card; Super+I opens
  webos-settings. The card appears exactly once per login in kitty, foot,
  TTY, ssh and any interactive bash/zsh/fish shell.
- fastfetch never prints "Image logo types are not supported"; failures go to
  /tmp/webos-fastfetch.log, not into the shell.
- Admin actions (mounting, package install, settings changes) raise a polkit
  password prompt instead of "not authorized".
- `webos-rice --doctor` reports every check OK as the logged-in user, and
  ~/.local/state/webos/rice.manifest is owned by that user.

INSTALLER
---------
Command: webos-installer
  --gui                  windowed egui installer
  --check                show detected disks, firmware and rootfs, then exit
  -d, --dry-run          run the wizard, write nothing
  -c, --config FILE -y   unattended install from a TOML file
      --unattended       with --config: no TTY, print the log
Log:   /var/log/webos-installer.log
Config: /etc/webos/install.toml (template on the live medium)

Profiles:
  Full      Hyprland + WebOS rice + gaming stack, SDDM
  Noctalia  Hyprland + Noctalia shell + gaming stack, SDDM
  Plasma    KDE Plasma 6 (Wayland) + gaming stack, SDDM
  Minimal   base system only, TTY login, no display manager

Dotfiles profiles (look only):
  ashen     WebOS Deep Black rice (default)
  mono      flat monochrome bar, grayscale kitty, square mako
  jakoolit  JaKooLit-inspired frosted glass top bar
  minimal   plain low-resource top bar

Installer options and defaults:
  gaming stack on, Steam note on, Firefox on, fish on, zsh on,
  Bluetooth on, GRUB on.
  Discord, OpenCode, Spotify, Vesktop, Waypaper, Flatpak, SSH server,
  firewall and NVIDIA are opt-in.
  Filesystem btrfs (or ext4/xfs), swap zram (or partition/none),
  ESP 512 MiB, LUKS2 optional, UEFI or BIOS.

The installer copies the live rootfs, then:
- applies the chosen dotfiles profile and rice for the account,
- enables services and the chosen session,
- removes Noctalia for non-Noctalia profiles,
- restores the D-Bus launch helper permissions,
- writes /etc/webos-release from /etc/os-release,
- removes the live-medium autologin/menu glue.

SESSIONS / LOGIN
----------------
SDDM is the greeter. Its session list comes from
/usr/share/webos/sessions/{wayland,x11}; the installer symlinks only the
selected session there, so upstream session files remain intact but hidden.

  webos-session              Hyprland + WebOS rice (default)
  webos-session --noctalia   Hyprland + Noctalia shell
  webos-session --gamescope  SteamOS-style gamescope session
  webos-session --safe       Hyprland with the rice disabled (debugging)

Session environment: Wayland, XDG_CURRENT_DESKTOP=Hyprland, Breeze_Light
cursor, dark GTK/Qt defaults. GPU hints are chosen from /sys/module/nvidia.

`webos-autostart hyprland` (portals + polkit + bar/shell + wallpaper),

SETTINGS

TERMINAL / SHELLS / FASTFETCH
-----------------------------
kitty and foot run /usr/bin/webos-shell, which prints the WebOS fastfetch card
once (WEBOS_FASTFETCH_SHOWN) and then execs $SHELL. bash, zsh and fish print
the same card on interactive login. Manual: `webos-fastfetch`.
Config: /usr/share/webos/rice/fastfetch/ (fastfetch.json, webos.txt).
Logo: text cobweb (no ImageMagick/chafa needed).
Modules: display, uptime, cpu, gpu, terminal, memory, disk, packages, shell,
datetime.
Theme: pure black, monochrome, thin white bar cursor, white selection.
Failures are logged to /tmp/webos-fastfetch.log.

GAMING / PERFORMANCE
--------------------
- zram swap: RAM/2 capped at 8 GiB, zstd, priority 100 (local.d webos.start).
- sysctl tuning: vm.swappiness=100, vfs_cache_pressure=50,
  vm.max_map_count=2147483642, split_lock_mitigate=0, netdev_max_backlog.
- gamemode, MangoHud, gamescope, vkBasalt, vkd3d-proton, Lutris, Heroic.
- `webos-gaming status`            what is running and with what
  `webos-gaming gamescope [cmd…]` run a command in gamescope
  `webos-gaming gamescope-session` SteamOS-style session
  `webos-gaming mangohud-toggle`  flip MangoHud
  `webos-gaming proton install|list` fetch/list Proton-GE
  `webos-gaming tune <profile>`   apply an scx/CPU profile
  `webos-gaming bench <cmd…>`     run with MangoHud + logging
- Steam and 32-bit Windows games need multilib. Options: Flatpak Steam
  (recommended), Distrobox, or a future multilib WebOS build. If selected,
  the installer writes /etc/webos/steam-unavailable.txt.
- NVIDIA: x11-drivers/nvidia-drivers is installed; nouveau is blacklisted.
  Choosing NVIDIA in the installer adds nvidia-drm.modeset=1 and dracut
  force_drivers. AMD/Intel systems ignore it.

TROUBLESHOOTING
---------------
- Rice missing/odd: `webos-rice --user --force`, then log out and in.
- No waybar: `webos-rice --toggle-panel` or run `waybar`; check
  `webos-rice --doctor` and /tmp/webos-autostart.log.
- fastfetch blank: run `webos-fastfetch`; read /tmp/webos-fastfetch.log.
  Remove WEBOS_FASTFETCH_SHOWN to force it in the current shell.
- No polkit prompt: check /tmp/webos-portals.log and that
  /usr/libexec/dbus-daemon-launch-helper is 4754 root:messagebus; restart
  the session or run `webos-portals`.
- Hyprland starts with no bar/autostart: confirm
  ~/.config/hypr/hyprland.lua is absent (renamed .webos-disabled) and that
  `Hyprland -c ~/.config/hypr/hyprland.conf` is used.
- Duplicate sessions in SDDM: only /usr/share/webos/sessions should be
  listed; check /etc/sddm.conf.d and /usr/share/xsessions.
- Noctalia appears unexpectedly: profile was not Noctalia; remove
  gui-apps/noctalia and its session entry, or reinstall with the right
  profile.
- No sound: `rc-service elogind status`, `pavucontrol`; PipeWire runs per
  user (wireplumber).
- Installer log: /var/log/webos-installer.log; install config
  /etc/webos/install.toml.
- Hyprland log: ~/.local/share/hyprland/hyprland.log.

KNOWN LIMITATIONS / NOTES
-------------------------
- 64-bit only image: no Wine, native Steam, winetricks, protontricks or
  goverlay. Use Flatpak Steam or Distrobox.
- KDE Plasma 6.8.3 is Wayland-only in this image (no startplasma-x11).
- niri is not included: it needs libdisplay-info < 0.4, which conflicts with
  the 0.4 slot required by Plasma/KWin 6.8.3.
- /usr/share/xsessions/Xsession.desktop is the standard xinit entry; SDDM
  does not offer it because WebOS points SessionDir at
  /usr/share/webos/sessions.
- No binary package host by default; updates compile from source.
- GitHub social preview cannot be set from the CLI.
