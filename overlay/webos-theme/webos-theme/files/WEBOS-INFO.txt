WebOS 1.03 "Ashen" — system information
========================================

Everything important about this installed system, in one file.
Installed copy: /usr/share/webos/WEBOS-INFO.txt
Repo copy:      overlay/webos-theme/webos-theme/files/WEBOS-INFO.txt

RELEASE / IDENTITY
------------------
- Version      : WebOS 1.03 "Ashen"
- Base         : Gentoo Linux, OpenRC + elogind (no systemd)
- Kernel       : sys-kernel/webos-kernel 6.12.119 LTS, localversion "-webos"
- Architecture : amd64, 64-bit only (ABI_X86="64", no multilib)
- Desktops     : Hyprland with the monochrome rice (default); regular Plasma
                 6.8.3 (Wayland) is an opt-in profile, never installed into a
                 Full/Minimal image
- Installer    : webos-installer (Rust TUI + optional egui GUI)
- Filesystems  : btrfs (default, subvolumes + zstd), ext4, xfs; optional LUKS2
- Bootloader   : GRUB2 (BIOS and UEFI)
- ISO          : webos-1.03-Ashen-amd64.iso (split parts + SHA256SUMS.txt)
- Source       : https://github.com/4NT1K/WebOS
- Release file : /etc/os-release and /etc/webos-release both report 1.03

QUICK START
-----------
1. Boot the ISO (Ventoy, Rufus, balenaEtcher or dd). The live menu appears on
   tty1: 1) install, 2) root shell, 3) inspect hardware.
2. Installer: choose disk, filesystem, swap, profile, dotfiles profile,
   account, timezone/locale/keymap, then confirm the summary.
3. Reboot, remove the medium, log in at SDDM (or the console for Minimal).
4. First login applies the rice; waybar, wallpaper, notifications, portals and
   the polkit agent start automatically.
5. Update with `sudo webos-update`.

WHAT CHANGED IN 1.03
--------------------
This is a clean maintenance rebuild of the Ashen image, built from a fresh
stage3 chroot rather than from a maintainer's installed system. It ships the
current source tree: `webos-theme-1.0-r51`, the redesigned music card, the
spotlight performance panel, full transparency support, no cava widget, and
the updater fix for the stale Vesktop entry. Existing 1.02 machines receive
the same tree with `sudo webos-update`. Log out and back in (or reboot) after
a theme update so the session picks up the new files.

- The far-right ⏻ power button is now present in the "mono" dotfiles profile as
  well as the rice profile. `webos-rice` migrates only the exact distro-generated
  legacy Waybar config, backs it up once as `.webos-orig`, and never
  touches a file you edited yourself.
- The lock screen no longer shows raw `<span foreground=` text. Hyprlang needs
  `##` for a literal colour, so the placeholder is `foreground="##7A7A7A"`.
- Obsolete `grace` and `no_fade_in` keys were removed from hyprlock.conf; they
  are CLI flags now: `hyprlock --grace 0 --no-fade-in`.
- Idle blanking uses Hyprland 0.57's real Lua DPMS dispatch:
  `hl.dispatch(hl.dsp.dpms({ action = "off" }))`. The dim listener is scoped to
  `/sys/class/backlight` with `brightnessctl -c backlight`, so keyboard LEDs
  are no longer changed by mistake.
- Waybar IPC is disabled in both rice and mono configs; the "socket path is
  empty" warning is gone.
- `webos-music` is a compact 340x340 layer-shell card under the bar. The current
  Spotify cover is cover-cropped and only lightly frosted (blur 2.5, full
  brightness, 0.06 dark overlay), then used as the whole card background. It
  slides down from above the panel.
- A spinning vinyl record sits in the middle of the card, drawn in GTK/Cairo
  with grooves, a fixed reflection and the current Spotify cover as its centre
  label; it spins only while Spotify plays. Text, buttons, the progress bar and
  the volume bar are pure black or white depending on `art_is_light()`: white
  on dark art, black on light art, with no glow, outline or button box. The
  title/artist are bold and slightly larger at the top left, the mute button
  is gone, and flat playback buttons sit directly under the elapsed/total
  progress bar. The slim flat volume bar stays on the right edge: dragging up
  raises the volume and dragging down lowers it, applied live while dragging.
  Dragging the seek previews it and seeks once on
  release. The centred Waybar pill shows only icon, title and artist.
  MPRIS/volume stay Spotify-only. No audio visualizer is installed.
- Clicking outside `webos-music` or `webos-stats` dismisses it. The transparent
  catcher is on the TOP layer and the card is above it on OVERLAY.
- Both dropdowns try `GtkLayerShell-0.1.typelib` before `1.0`, which is the
  typelib WebOS actually ships, and clear stale Hyprland error overlays.
- `webos-update` keeps the binary-first `--getbinpkg` default and adds
  `--fast` / `--fast-binpkg`, `--strict-use` / `--respect-use`, `--buildpkg`
  and `--no-compile`. It still refuses to force a binary with wrong USE flags:
  `-G`, `-K` and `--binpkg-respect-use=n` are deliberately not used.
- Installer, Manifest, kernel-fragment, build-script and watcher audit defects
  were corrected, and the shipped guide and release notes now describe 1.03.

RECENT THEME REVISIONS (r41-r51)
--------------------------------
- r41/r42: spectrum bars became solid opaque white and the cover was lightly frosted
  instead of heavily dimmed, so the artwork stayed recognisable.

  the current cover (black on a fairly white cover); track changes are faster
  because the card polls once per 250 ms with one playerctl call and prepares art

- r46: floating windows animate when toggled.

  the card keeps its elapsed/total bar. The old spectrum bars became a spinning vinyl
  with the cover as the centre label, title/artist got bolder and larger, the
  mute button was removed, flat playback buttons moved below the progress bar,
  and the volume control became a small flat vertical bar on the right edge.
  Text, buttons and both bars are pure black or white with no glow based on
  `art_is_light()`. Spotify remains the only MPRIS player and the only audio
  stream the card reads or changes.
- r48: dragging the seek bar previews it; dropping seeks once to that point and
  playback continues from there instead of the bar sliding or snapping back.
  Volume drags are previewed and eased in small steps, still Spotify-only. A
  long song title wraps onto a second line instead of being cut off.
- r49: the volume control stays a slim flat vertical bar on the right edge,
  but now changes Spotify's level continuously while dragging (up louder,
  down quieter) rather than only on release.
- r50: `webos-update` also removes retired Vesktop entries from custom Portage
  sets. Older images left one in `/etc/portage/sets/desktop`, so `@world`

- r51: removed the Waybar spectrum module and its helper, and dropped cava from

WHAT CHANGED IN THE ORIGINAL 1.021 (HISTORICAL — SUPERSEDED BY 1.01)
-------------------------------------------------------------------
This was an old fix release for the issues reported against 1.02:
- Hyprland loaded the stock ~/.config/hypr/hyprland.lua instead of the WebOS
  hyprland.conf. 1.021 tried to move the lua aside and pin hyprland.conf.
  That approach was wrong (Hyprland 0.57 ignores hyprland.conf); 1.022
  rewrites the rice in Lua instead. See below.
- polkitd could not be D-Bus activated: an ownership pass had stripped setuid
  from /usr/libexec/dbus-daemon-launch-helper. It is now 4754 root:messagebus
  in the rootfs, live image and installer, and ownership normalisation no
  longer chowns root-owned files.
- fastfetch failed with "Image logo types are not supported" (built without
  native image/chafa support). At the time the shipped config used the text
  cobweb logo (`logo.type = file`, webos.txt), which renders everywhere. 1.01
  replaces that with chafa symbol art; see the FASTFETCH section below.
- fastfetch now appears in every interactive shell: bash, zsh and fish hooks
  are installed, foot uses webos-shell like kitty, and WEBOS_FASTFETCH_SHOWN
  prevents duplicate cards.
- The TUI installer progress bar lost its "%" sign, mixed a thin track with a
  thick fill, drifted out of its panel and ran past the border. It is now a
  custom two-line widget: percentage/phase on one line, a full-width track of
  filled/empty cells below, sized from the panel's real inner width.
- /home/*/.local/state/webos/rice.manifest was root-owned and unreadable.
  webos-rice and webos-dotfiles now return state/config files to the home
  directory owner; `webos-rice --doctor` no longer uses an unset ${home}.
- Duplicate/stale SDDM entries: webos.desktop is no longer installed into
  /usr/share/xsessions (Hyprland is Wayland-only). webos.desktop was reused for
  the WebOS Wayland session; a later 1.022 note claimed the installer linked
  every installed desktop. That claim is obsolete: the final rule is one
  session only (see SESSIONS / LOGIN).
- The monochrome rice is the only WebOS look. Every install applies it; there
  is no appearance page in the installer and no alternate shell to choose.
  Advanced dotfiles profiles remain expert CLI options.
- /etc/webos-release was hard-coded to "1.01 (Ashen)" and written twice. It
  now derives the version from the installed /etc/os-release. The current
  release is 1.01 "Ashen".
- Same-version rebuilds could keep a stale installer/theme. The rootfs stage
  now unmerges and rebuilds app-admin/webos-installer and webos-theme.
- `webos-rice --doctor` no longer fails the Inter/JetBrains Mono checks when
  fc-list is unavailable, and no longer fails "greetd configured" on healthy
  SDDM systems.

WHAT WAS FIXED IN 1.022 (HISTORICAL — SUPERSEDED BY 1.01)
---------------------------------------------------------
This section is retained for history. 1.022 was a fix release for the issues
found in the 1.021 audit; its SDDM "all installed desktops" note below was
later reversed and is not the behaviour of 1.01:
- **The rice never actually loaded.** Hyprland 0.57 reads Lua configuration
  and ignores hyprland.conf completely, so 1.021's "move the lua aside" fix
  made the compositor fall back to its built-in defaults: no keybinds, no
  autostart, no blur. The whole rice is now `hyprland.lua` plus a small
  `webos-colors.lua` palette module; hyprland.conf is gone. Verified with
  `Hyprland --verify-config`.
- webos-rice replaces only the untouched upstream lua example (the one with
  the `This is an example Hyprland Lua config file.` header). A config you
  edited is still left alone. It also removes its own old hyprland.conf.
- webos-session launches `Hyprland -c ~/.config/hypr/hyprland.lua`, which loads
  the WebOS mono rice, keybinds and autostart from that file. --safe still uses
  `-c /dev/null` for debugging.
- `webos-rice --doctor` checks that `~/.config/hypr/hyprland.lua` exists and
  is the WebOS config, and that `webos-colors.lua` is present.
- **hyprlock had no logo.** `/usr/share/webos/logo.svg` was installed from
  the wallpaper SVG, a 3840x2160 black rectangle, so the lock screen drew an
  invisible black square. It now installs the real 512x512 logo.
- **hyprsunset was never started** and used `gamma = 90`/`100` where the
  option is a multiplier (1.0 = 100%). It starts with the session. In 1.01 the
  single neutral profile uses `time = 00:00`, `identity = true`,
  `temperature = 6500` and `gamma = 1.0`; there is no evening warm-up.
- hypridle had a 60-second listener that ran a `hyprctl`/`jq` pipeline and
  could not inhibit anything. Removed: hypridle honours the D-Bus idle
  inhibitor that games and video players already take.
- `webos-portals` used `pgrep -f xdg-desktop-portal`, which also matches the
  `-gtk` and `-hyprland` backends and made the script think the portal it was
  about to start was already running. It now compares argv[0] exactly.
- `webos-rice --doctor` reported "font: JetBrains Mono NF" as failed even
  though the font was installed. The check used `grep -q` under
  `set -o pipefail`: grep exited at the first match, fc-list died from
  SIGPIPE and the pipeline returned 141. The font checks now read the whole
  fc-list stream and use `find ... -print -quit` as the fallback.
- Session services (waybar, hypridle, hyprpaper, portals, polkit agent) could
  be missing when the user's ~/.config/hypr/ config predated the autostart
  lines. webos-session now starts webos-autostart itself once the compositor
  answers; webos-autostart uses a directory lock in $XDG_RUNTIME_DIR and
  starts only what is not already running, so the copy in the Lua config is a
  no-op. /tmp/webos-autostart.log and /tmp/webos-portals.log always record
  the attempt.
- `webos-rice --wallpaper` called a `hyprctl keyword wallpaper` that does not
  exist. It now writes hyprpaper.conf, preloads the image over hyprpaper IPC
  and falls back to swaybg. The wallpaper menu uses fzf when present and
  wofi otherwise.
- SDDM: 10-webos.conf no longer sets DisplayServer (Gentoo's 01gentoo.conf
  selects the greeter backend) and the installer no longer duplicates
  DefaultSession. The session chosen at install time is still seeded in
  /var/lib/sddm/state.conf.

WHAT CHANGED IN 1.0
-------------------
First stable release, rebuilt from the 1.022 tree with the final audit fixes:
- Only the desktop chosen in the installer is linked into SDDM, so the login
  screen shows one session instead of a list of every installed desktop.
- regular Plasma was in the default @desktop set and leaked into every image.
  It now lives in the opt-in @plasma set; non-Plasma installs unmerge it and
  remove its session entry. The Plasma profile still installs and themes it.
- Keybinds: Super+Q opens kitty, Super+C closes the window, Super+Shift+S is
  the screenshot snip, and exit moved to Super+Shift+Escape so Q no longer
  means two different things.
- zram now comes up at boot: the kernel fragment enables the zstd backend
  (the old CONFIG_ZRAM_DEF_COMP_ZSTD symbol was ignored), the boot glue falls
  back to lzo-rle and logs failures, and the doctor checks swap is active.
- ananicy-cpp is enabled under its real OpenRC name, ananicy-cpp.initd, and
  started at install time.
- The mono bar no longer prints the LAN IPv4 address or a battery percentage;
  its power pill was removed in the original 1.01 image along with cpu, memory
  and pulseaudio. 1.03 restores ⏻; the right cluster is waypaper, clock,
  tray, performance and power.
- kitty transparency is restored: kitty owns the alpha value (0.82) and the
  compositor no longer multiplies a second opacity over it; the framed
  fastfetch card is back. 1.01 uses `auto` for bold/italic fonts and a refined
  greyscale ANSI ramp.
- webos-update now updates sys-kernel/webos-kernel explicitly (it is not in
  @world) and regenerates /boot/grub/grub.cfg when a new kernel lands.
- The installer log path in this document now matches the real file,
  /var/log/webos-install.log, and stale rice-manifest entries are pruned.

SESSIONS / LOGIN
----------------
SDDM is the greeter. Its session list comes from
/usr/share/webos/sessions/{wayland,x11}. The installer clears that directory
and symlinks ONLY the .desktop file for the profile chosen in the installer, so
the greeter shows one session rather than every desktop installed on the image.
That session is also recorded as the default in /var/lib/sddm/state.conf.
Upstream session files under /usr/share/wayland-sessions remain intact. The
older 1.022 "link every installed desktop" behaviour is not used in 1.01.

  webos-session              Hyprland + WebOS mono rice (default)
  webos-session --gamescope  SteamOS-style gamescope session
  webos-session --safe       Hyprland with the rice disabled (debugging)

Session environment: Wayland, XDG_CURRENT_DESKTOP=Hyprland, Breeze_Light
cursor, dark GTK/Qt defaults. GPU hints are set only when the hardware is
unambiguous (NVIDIA or AMD); Intel uses Mesa's auto-detection.

POWER / SESSION ACTIONS
----------------------
WebOS runs OpenRC + elogind and does not install systemd, so there is no
`systemctl`. Every power action goes through logind:

  wlogout buttons    loginctl reboot | poweroff | suspend | hibernate
  Hyprland idle      loginctl suspend (rice/hypr/hypridle.conf)
  Waybar ⏻           click opens wlogout
  Screen lock        hyprlock

`reboot` and `poweroff` are plain (non-setuid) sysvinit symlinks and will fail
from a user session; use the menu or `loginctl ...` instead. Services are still
managed with `rc-service`/`rc-update` (see SERVICES below).

HYPRLAND

/usr/share/webos/rice/hypr/). Hyprland 0.57 reads Lua configuration and
ignores hyprland.conf. webos-rice never overwrites a file you edited unless
you pass --force; edits are tracked by hash in the rice manifest. Put local
changes in ~/.config/hypr/local.lua — hyprland.lua loads it if it exists.

Autostart (`hl.on("hyprland.start")`): dbus activation environment,

SETTINGS
--------
`webos-settings` is session-aware:
- Plasma: launches KDE System Settings (regular Plasma 6.8.3, Wayland opt-in).
- Hyprland: webos-menu (curated wofi launcher) for Display (wdisplays), Input
  devices (hyprctl devices), KDE System Settings, Audio (pavucontrol), Network
  (nm-connection-editor), Wallpaper (waypaper), Bluetooth (blueman-manager),
  Power/session (wlogout).
- `webos-settings --display` and `--input` go straight to the relevant tool.

RICE / THEMING
--------------
Source of truth: /usr/share/webos/rice (hypr, waybar, wofi, kitty, foot,
fish, fastfetch, mako, wlogout, gtk-3.0/4.0, qt5ct/qt6ct, kvantum, plasma,
konsole, color-schemes, wallpapers).
Dotfiles profiles: /usr/share/webos/dotfiles/{jakoolit,minimal,mono}. These are
expert CLI options for advanced users; the installer has no appearance page.
Per-user copies: ~/.config/<app>, ~/.local/share/color-schemes/DeepBlack.colors,
Plasma configs (kdeglobals, kwinrc, kwinrulesrc), ~/.local/share/konsole.

Palette (refined Ashen greyscale): #000000 base, rgba(0,0,0,0.92) panels,
#D8D8D8 text, #E8E8E8 accents/cursor/url, #7A7A7A dim, #4A4A4A faint,
rgba(232,232,232,0.20) borders and rgba(232,232,232,0.35) on hover. The grey
ramp is #a6a6a6, #c2c2c2, #d8d8d8, #e8e8e8; where a plain RGB triplet is needed
(fastfetch, Konsole, Plasma colour scheme) use 216,216,216 for text and
122,122,122 for dim. Greyscale ANSI 0-15 runs through kitty, foot and Konsole.
kitty uses JetBrainsMono Nerd Font with `auto` bold/italic faces and
background_opacity 0.82; Hyprland leaves kitty's alpha alone.
Plasma: Deep Black scheme, Breeze_Light cursor, matching wallpaper and
Konsole profile, KWin blur/opacity rule for kitty. Hyprland: smoothed
animations, blurred near-opaque surfaces, same palette.

  webos-dotfiles --apply mono|ashen|jakoolit|minimal [--system] [--force]
  webos-plasma-setup             apply the Plasma side of the theme

TERMINAL / SHELLS / FASTFETCH
-----------------------------
kitty and foot run /usr/bin/webos-shell, which prints the WebOS fastfetch card
once (WEBOS_FASTFETCH_SHOWN) and then execs $SHELL. bash, zsh and fish print
the same card on interactive login. Manual: `webos-fastfetch`.
Config: /usr/share/webos/rice/fastfetch/fastfetch.json (plus the shipped PNG
and the webos.txt fallback). Ten modules: display, uptime, cpu, gpu, terminal,
memory, disk, packages, shell, datetime.

Logo: this fastfetch build has NO native image, kitty graphics, sixel or
ImageMagick logo support — those logo types fail with "Image logo types are not
supported". The shipped PNG is therefore rendered as coloured chafa **symbol
art** (not a terminal image) via `logo.type = "command-raw"` and
`logo.source = "webos-chafa-logo"`, which emits a fixed-width 16x16 grid.
`webos.txt` is a fallback only, used automatically when chafa is absent or the
command-raw logo fails. Failures are logged to /tmp/webos-fastfetch.log.

Theme: pure black, greyscale, thin soft-white bar cursor, soft-white selection,
output 38;2;216;216;216 and separators 38;2;122;122;122.

DESKTOP PANELS / REFRESH
------------------------
Waybar (top, rounded translucent capsules, surface rgba(0,0,0,0.92)):
  left   workspaces and focused window title
  centre mpris pill — click it or press Super+M to toggle the music dropdown
  right  ▧ waypaper, ⟳ update badge, clock, tray, ▾ performance, ⏻ power
The cpu, memory and pulseaudio pills, and any aliases for them, are gone; there
is still no network or battery module. The far-right ⏻ pill opens wlogout.

- Music (`webos-music`): a GTK3 layer-shell dropdown under the bar showing the
  current Spotify cover as a lightly frosted background, bold title/artist at
  the top left, PLAYING/PAUSED status, a spinning vinyl with the cover as its
  centre label, a seekable elapsed/total bar and flat outline-free playback
  buttons directly beneath it. Text, buttons and both bars switch between
  plain white (dark art) and plain black (light art). A slim flat vertical
  volume bar sits on the right edge. The Waybar
  pill shows only icon/title/artist. Spotify's own stream volume is the only
  one changed. No extra widget framework is required.
- Performance (`webos-stats`): the ▾ pill opens a small corner dropdown with
  CPU, GPU, VRAM, RAM, DISK and TEMP bars. RAM shows actual used/total GiB, and
  CPU lists every core (`c0   2% 53C`) with usage plus a hwmon temperature;
  `k10temp`/`coretemp`/`zenpower`/`cpu` are preferred over stale `acpitz`
  zones. GPU and VRAM show `n/a` without `nvidia-smi`.
- Power (`⏻`, far right): opens `wlogout`; tooltip is "Power — open session
  menu (reboot, shut down, suspend)". All buttons use `loginctl` verbs. See
  POWER / SESSION ACTIONS below.
- Waypaper (`▧`): the pill launches `waypaper` directly to choose a wallpaper.
- Refresh (`webos-refresh`): saves and restores exact monitor modes at login and
  watches live changes from wdisplays/wlr-randr.
    webos-refresh status        compare current and saved modes
    webos-refresh set <hz>      choose a rate from the mode's advertised modes
  The saved default is the 170 Hz mode `1920x1080@169.99699`, pinned in
  hyprland.lua and persisted by webos-refresh. Only modes advertised in
  `availableModes` can be persisted; the old 60 Hz / 119.98 Hz test notes are
  obsolete.
- Palette: see RICE / THEMING above. The same greyscale is repeated across the
  rice files and the accent-cycling scripts, not generated from a template.

  vm.max_map_count=2147483642, split_lock_mitigate=0, netdev_max_backlog.
- gamemode, MangoHud, gamescope, vkBasalt, vkd3d-proton, Lutris, Heroic.

UPDATES / PACKAGES
------------------
Portage + OpenRC. `webos-update` and `emerge` prefer prebuilt binaries:
`EMERGE_DEFAULT_OPTS` includes `--getbinpkg`, and
`/etc/portage/binrepos.conf/gentoo.conf` pins Gentoo's
`releases/amd64/binpackages/23.0/x86-64-v3` binhost. A binary is used only when
its version, USE flags and CPU flags match; mismatches, `~amd64` packages newer
than the binhost and WebOS/overlay-only packages fall back to source. We
deliberately do NOT use `-G`, `-K` or `--binpkg-respect-use=n`, so a binary with
wrong USE flags is never forced onto the machine. `webos-update` reports which
updates were binary vs source and prints an honest total; the Waybar update
counter accepts both `[binary` and `[ebuild` emerge lines.
Repos: gentoo, webos (local overlay /usr/local/portage/webos); build-only
overlays may be disabled under /etc/portage/repos.conf.disabled.

  sudo webos-update              refresh WebOS overlay, sync repos, rebuild
                                 @world, depclean, config, kernel + GRUB,
                                 Flatpak, rice; log /var/log/webos-update.log
  sudo webos-update --check      show what would change
  sudo webos-update --yes        non-interactive config merges
  --fast | --fast-binpkg         faster binaries (--binpkg-changed-deps=n),
                                  still with strict USE matching
  --strict-use | --respect-use   force --binpkg-respect-use=y
  --buildpkg                     cache remaining source builds locally
  --no-compile                   abort if any source build would be needed
  --no-sync | --no-flatpak | --no-depclean | --no-kernel | --quiet

  Run `sudo webos-update` yourself when the Waybar badge appears; nothing
  applies updates automatically. webos-update first refreshes the local WebOS
  overlay from GitHub (auto-sync=no, so emerge --sync alone would never see new
  WebOS ebuilds), rebuilds @world, and explicitly updates sys-kernel/webos-kernel
  (it is not in @world). It regenerates /boot/grub/grub.cfg when a new kernel
  image lands and tells you to reboot.
  Kernel security fixes are shipped as a new ebuild revision in the WebOS repo;
  one `webos-update` on each machine picks them up. Manual Portage commands
  remain available below.

  sudo emerge --sync
  sudo emerge -av <package>
  sudo emerge -avuDN @world
  sudo emerge --depclean
  sudo dispatch-conf

TROUBLESHOOTING
---------------
- Rice missing/odd: `webos-rice --user --force`, then log out and in.
- No waybar: `webos-rice --toggle-panel` or run `waybar`; check
  `webos-rice --doctor` and /tmp/webos-autostart.log.
- fastfetch blank: run `webos-fastfetch`; read /tmp/webos-fastfetch.log.
  Remove WEBOS_FASTFETCH_SHOWN to force it in the current shell.
- No polkit prompt: check /tmp/webos-portals.log and that
  /usr/libexec/dbus-daemon-launch-helper is 4754 root:messagebus; restart
  the session or run `webos-portals`.
- Hyprland starts with no bar/autostart: check
  ~/.config/hypr/hyprland.lua exists and starts with the WebOS header (not
  the upstream example), run `webos-rice --doctor`, and look at
  /tmp/webos-autostart.log. `webos-rice --user --force` restores it.
- More than one session in SDDM: the greeter lists /usr/share/webos/sessions,
  which the installer fills with only the chosen profile. A second entry means
  a stale .desktop was left in that directory; remove it and check
  /etc/sddm.conf.d/20-webos-session.conf. Plasma should not be there unless
  the Plasma profile was chosen.
- No sound: `rc-service elogind status`, `pavucontrol`; PipeWire runs per
  user (wireplumber).
- Installer log: /var/log/webos-install.log; install config
  /etc/webos/install.toml.
- Compositor problems: check `webos-rice --doctor`, /tmp/webos-autostart.log
  and `journalctl --user -b`; Hyprland logs to stdout and WebOS does not
  configure a dedicated Hyprland log file.

KNOWN LIMITATIONS / NOTES
-------------------------
- 64-bit only image: no Wine, native Steam, winetricks, protontricks or
  goverlay. Use Flatpak Steam or Distrobox.
- regular Plasma 6.8.3 (opt-in profile) is Wayland-only here (no startplasma-x11).
- /usr/share/xsessions/Xsession.desktop is the standard xinit entry; SDDM
  does not offer it because WebOS points SessionDir at
  /usr/share/webos/sessions.
- Gentoo binaries are used only when version/USE/CPU flags match; with
  `~amd64` and WebOS-specific flags, some updates still compile from source.
  WebOS-only and overlay packages always compile from source.
- No `systemctl`: use `loginctl` for power actions and `rc-service`/`rc-update`
  for services.
- GitHub social preview cannot be set from the CLI.

MAINTAINER / RELEASE WORKFLOW (FROM WEBOS ITSELF)
-------------------------------------------------
You do not need to boot another distro to publish an update. On a running
WebOS system, as root:

  git clone https://github.com/4NT1K/WebOS.git
  cd WebOS
  emerge -av dev-vcs/git dev-lang/rust app-arch/p7zip dev-util/github-cli  # build/publish tools
  gh auth login                 # authenticate once for release uploads
  ./build.sh fetch              # stage3, portage, kernel patches, overlays, crate vendor
  ./build.sh bootstrap          # fresh chroot (or reuse an existing one)
  ./build.sh kernel
  ./build.sh rootfs             # includes this WEBOS-INFO.txt via webos-theme
  bash scripts/50-check.sh      # source regression guards: must report 0 problems
  ./build.sh iso                # build/webos-1.03-Ashen-amd64.iso

Verify before publishing: `webos-update --check`, `waypaper --help`,
`webos-stats` core/RAM output, and that the ISO's `webos/version` matches
`WEBOS_VERSION=1.03-Ashen`. Keep the USB stick mounted, then copy the ISO over
the old one on Ventoy (and refresh `webos-version.txt`), split it for GitHub,
verify `sha256sum -c SHA256SUMS.txt`, and publish a **new** `v1.03` release with
`gh release create v1.03 --notes-file docs/releases/v1.03.md --latest ...`.
Keep `v1.01` untouched as the historical release. Never shut the machine down
as part of a release; only reboot when you deliberately test the new kernel.

Source of truth for identity is `branding/version` (`WEBOS_VERSION="1.03"`).
Maintenance fixes that must reach installed machines need a new package
revision (`webos-theme-1.0-r51`) and a new tag; `webos-update` refreshes the
overlay from `main`, so commit and push the source before publishing assets.
Before wiping another OS's drive, keep a verified backup and confirm WebOS
boots and installs from its own SSD.
