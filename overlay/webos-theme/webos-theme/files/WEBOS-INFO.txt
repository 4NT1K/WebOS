WebOS 1.0 "Ashen" — system information
========================================

Everything important about this installed system, in one file.
Installed copy: /usr/share/webos/WEBOS-INFO.txt
Repo copy:      overlay/webos-theme/webos-theme/files/WEBOS-INFO.txt

RELEASE / IDENTITY
------------------
- Version      : WebOS 1.0 "Ashen"
- Base         : Gentoo Linux, OpenRC + elogind (no systemd)
- Kernel       : sys-kernel/webos-kernel 6.12 LTS, localversion "-webos"
- Architecture : amd64, 64-bit only (ABI_X86="64", no multilib)
- Desktops     : Hyprland with the monochrome rice (default); regular Plasma
                 is an opt-in profile, never installed into a Full/Minimal image
- Installer    : webos-installer (Rust TUI + optional egui GUI)
- Filesystems  : btrfs (default, subvolumes + zstd), ext4, xfs; optional LUKS2
- Bootloader   : GRUB2 (BIOS and UEFI)
- ISO          : webos-1.0-Ashen-amd64.iso (split parts + SHA256SUMS.txt)
- Source       : https://github.com/4NT1K/WebOS
- Release file : /etc/os-release and /etc/webos-release both report 1.0

QUICK START
-----------
1. Boot the ISO (Ventoy, Rufus, balenaEtcher or dd). The live menu appears on
   tty1: 1) install, 2) root shell, 3) inspect hardware.
2. Installer: choose disk, filesystem, swap, profile, dotfiles profile,
   account, timezone/locale/keymap, then confirm the summary.
3. Reboot, remove the medium, log in at SDDM (or the console for Minimal).
4. First login applies the rice; waybar, wallpaper, notifications, portals and
   the polkit agent start automatically.
5. Update with `sudo webos-update`.

WHAT CHANGED IN 1.021
---------------------
This was a fix release for the issues reported against 1.02:
- Hyprland loaded the stock ~/.config/hypr/hyprland.lua instead of the WebOS
  hyprland.conf. 1.021 tried to move the lua aside and pin hyprland.conf.
  That approach was wrong (Hyprland 0.57 ignores hyprland.conf); 1.022
  rewrites the rice in Lua instead. See below.
- polkitd could not be D-Bus activated: an ownership pass had stripped setuid
  from /usr/libexec/dbus-daemon-launch-helper. It is now 4754 root:messagebus
  in the rootfs, live image and installer, and ownership normalisation no
  longer chowns root-owned files.
- fastfetch failed with "Image logo types are not supported" (built without
  ImageMagick/chafa). The shipped config uses the text cobweb logo
  (`logo.type = file`, webos.txt), which renders everywhere.
- fastfetch now appears in every interactive shell: bash, zsh and fish hooks
  are installed, foot uses webos-shell like kitty, and WEBOS_FASTFETCH_SHOWN
  prevents duplicate cards.
- The TUI installer progress bar lost its "%" sign, mixed a thin track with a
  thick fill, drifted out of its panel and ran past the border. It is now a
  custom two-line widget: percentage/phase on one line, a full-width track of
  filled/empty cells below, sized from the panel's real inner width.
- /home/*/.local/state/webos/rice.manifest was root-owned and unreadable.
  webos-rice and webos-dotfiles now return state/config files to the home
  directory owner; `webos-rice --doctor` no longer uses an unset ${home}.
- Duplicate/stale SDDM entries: webos.desktop is no longer installed into
  /usr/share/xsessions (Hyprland is Wayland-only). The installer points SDDM
  at /usr/share/webos/sessions and links every desktop that is actually
  installed (WebOS, Plasma, gamescope), with the profile chosen in the
  installer as the default. An earlier build linked only the chosen session,
  which left an installed Plasma unreachable from the greeter.
- The monochrome rice is the only WebOS look. Every install applies it; there
  is no appearance page in the installer and no alternate shell to choose.
- /etc/webos-release was hard-coded to "1.01 (Ashen)" and written twice. It
  now derives the version from the installed /etc/os-release.
- Same-version rebuilds could keep a stale installer/theme. The rootfs stage
  now unmerges and rebuilds app-admin/webos-installer and webos-theme.
- `webos-rice --doctor` no longer fails the Inter/JetBrains Mono checks when
  fc-list is unavailable, and no longer fails "greetd configured" on healthy
  SDDM systems.

WHAT WAS FIXED IN 1.022
-----------------------
This is a fix release for the issues found in the 1.021 audit:
- **The rice never actually loaded.** Hyprland 0.57 reads Lua configuration
  and ignores hyprland.conf completely, so 1.021's "move the lua aside" fix
  made the compositor fall back to its built-in defaults: no keybinds, no
  autostart, no blur. The whole rice is now `hyprland.lua` plus a small
  `webos-colors.lua` palette module; hyprland.conf is gone. Verified with
  `Hyprland --verify-config`.
- webos-rice replaces only the untouched upstream lua example (the one with
  the `This is an example Hyprland Lua config file.` header). A config you
  edited is still left alone. It also removes its own old hyprland.conf.
- webos-session launches `Hyprland -c ~/.config/hypr/hyprland.lua`, which loads
  the WebOS mono rice, keybinds and autostart from that file. --safe still uses
  `-c /dev/null` for debugging.
- `webos-rice --doctor` checks that `~/.config/hypr/hyprland.lua` exists and
  is the WebOS config, and that `webos-colors.lua` is present.
- **hyprlock had no logo.** `/usr/share/webos/logo.svg` was installed from
  the wallpaper SVG, a 3840x2160 black rectangle, so the lock screen drew an
  invisible black square. It now installs the real 512x512 logo.
- **hyprsunset was never started** and used `gamma = 90`/`100` where the
  option is a multiplier (1.0 = 100%). It starts with the session and the
  profiles use `gamma = 1.0`.
- hypridle had a 60-second listener that ran a `hyprctl`/`jq` pipeline and
  could not inhibit anything. Removed: hypridle honours the D-Bus idle
  inhibitor that games and video players already take.
- `webos-portals` used `pgrep -f xdg-desktop-portal`, which also matches the
  `-gtk` and `-hyprland` backends and made the script think the portal it was
  about to start was already running. It now compares argv[0] exactly.
- `webos-rice --doctor` reported "font: JetBrains Mono NF" as failed even
  though the font was installed. The check used `grep -q` under
  `set -o pipefail`: grep exited at the first match, fc-list died from
  SIGPIPE and the pipeline returned 141. The font checks now read the whole
  fc-list stream and use `find ... -print -quit` as the fallback.
- Session services (waybar, hypridle, hyprpaper, portals, polkit agent) could
  be missing when the user's ~/.config/hypr/ config predated the autostart
  lines. webos-session now starts webos-autostart itself once the compositor
  answers; webos-autostart uses a directory lock in $XDG_RUNTIME_DIR and
  starts only what is not already running, so the copy in the Lua config is a
  no-op. /tmp/webos-autostart.log and /tmp/webos-portals.log always record
  the attempt.
- `webos-rice --wallpaper` called a `hyprctl keyword wallpaper` that does not
  exist. It now writes hyprpaper.conf, preloads the image over hyprpaper IPC
  and falls back to swaybg. The wallpaper menu uses fzf when present and
  wofi otherwise.
- SDDM: 10-webos.conf no longer sets DisplayServer (Gentoo's 01gentoo.conf
  selects the greeter backend) and the installer no longer duplicates
  DefaultSession. The session chosen at install time is still seeded in
  /var/lib/sddm/state.conf.

WHAT CHANGED IN 1.0
-------------------
First stable release, rebuilt from the 1.022 tree with the final audit fixes:
- Only the desktop chosen in the installer is linked into SDDM, so the login
  screen shows one session instead of a list of every installed desktop.
- regular Plasma was in the default @desktop set and leaked into every image.
  It now lives in the opt-in @plasma set; non-Plasma installs unmerge it and
  remove its session entry. The Plasma profile still installs and themes it.
- Keybinds: Super+Q opens kitty, Super+C closes the window, Super+Shift+S is
  the screenshot snip, and exit moved to Super+Shift+Escape so Q no longer
  means two different things.
- zram now comes up at boot: the kernel fragment enables the zstd backend
  (the old CONFIG_ZRAM_DEF_COMP_ZSTD symbol was ignored), the boot glue falls
  back to lzo-rle and logs failures, and the doctor checks swap is active.
- ananicy-cpp is enabled under its real OpenRC name, ananicy-cpp.initd, and
  started at install time.
- The mono bar no longer prints the LAN IPv4 address or a battery percentage;
  its power menu is unchanged. The default bar no longer prints an IP either.
- kitty transparency is restored: kitty owns the alpha value (0.80-0.82) and
  the compositor no longer multiplies a second opacity over it; the framed
  fastfetch card is back.
- webos-update now updates sys-kernel/webos-kernel explicitly (it is not in
  @world) and regenerates /boot/grub/grub.cfg when a new kernel lands.
- The installer log path in this document now matches the real file,
  /var/log/webos-install.log, and stale rice-manifest entries are pruned.

EXPECTED BEHAVIOUR
------------------
Boot / live medium
- The banner reads "WebOS 1.0 (Ashen) — live medium".
- Nothing is written to disk until the summary is confirmed.
- The installer progress panel stays inside its border, keeps the "%" sign,
  and shows one consistent bar: red 0-25%, light red/orange 26-50%, yellow
  51-75%, light green 76-100%. ANSI colours survive the Linux console.

SDDM / sessions
- The greeter lists exactly one session: the profile chosen in the installer.
  Full -> "WebOS", Plasma -> "Plasma (Wayland)". No extra session is offered.
- Minimal installs no display manager and boots to a TTY login.
- regular Plasma is opt-in and Wayland-only; there is no Plasma X11 entry, and
  a non-Plasma install has no Plasma desktop packages.
- The installer removes any leftover alternate shell from the live image, so
  the installed system has only the chosen profile's session.

Hyprland (all rice profiles)
- waybar appears, wallpaper is set, mako shows notifications, hypridle runs,
  hyprpaper keeps the wallpaper, and portals + a polkit agent are active.
- Super+Q opens kitty with the framed WebOS fastfetch card; Super+I opens
  webos-settings. The card appears exactly once per login in kitty, foot,
  TTY, ssh and any interactive bash/zsh/fish shell. kitty is translucent.
- Super+Shift+S snips a screen region to ~/Pictures/Screenshots and the
  clipboard.
- fastfetch never prints "Image logo types are not supported"; failures go to
  /tmp/webos-fastfetch.log, not into the shell.
- Admin actions (mounting, package install, settings changes) raise a polkit
  password prompt instead of "not authorized".
- `webos-rice --doctor` reports every check OK as the logged-in user, and
  ~/.local/state/webos/rice.manifest is owned by that user.

INSTALLER
---------
Command: webos-installer
  --gui                  windowed egui installer
  --check                show detected disks, firmware and rootfs, then exit
  -d, --dry-run          run the wizard, write nothing
  -c, --config FILE -y   unattended install from a TOML file
      --unattended       with --config: no TTY, print the log
Log:   /var/log/webos-install.log
Config: /etc/webos/install.toml (template on the live medium)

Profiles:
  Full      Hyprland + WebOS mono rice + gaming stack, SDDM
  Plasma    regular Plasma (Wayland) + gaming stack, SDDM (opt-in @plasma set)
  Minimal   base system only, TTY login, no display manager

Appearance: one look only — the monochrome rice (floating rounded top-bar
pills, grayscale kitty, square mako). No appearance page in the installer.

Installer options and defaults:
  gaming stack on, Steam note on, Firefox on, fish on, zsh on, Flatpak on,
  Bluetooth on, GRUB on.
  Discord, OpenCode, Spotify, Vesktop, Waypaper, SSH server,
  firewall and NVIDIA are opt-in.
  Filesystem btrfs (or ext4/xfs), swap zram (or partition/none),
  ESP 512 MiB, LUKS2 optional, UEFI or BIOS.

The installer copies the live rootfs, then:
- applies the monochrome rice and dotfiles for the account,
- enables services and the chosen session,
- strips any alternate shell from the live image,
- restores the D-Bus launch helper permissions,
- writes /etc/webos-release from /etc/os-release,
- removes the live-medium autologin/menu glue.

SESSIONS / LOGIN
----------------
SDDM is the greeter. Its session list comes from
/usr/share/webos/sessions/{wayland,x11}. The installer clears that directory
and symlinks only the .desktop file for the chosen profile, so the greeter
shows one session rather than every desktop installed on the image. Upstream
session files under /usr/share/wayland-sessions remain intact.

  webos-session              Hyprland + WebOS mono rice (default)
  webos-session --gamescope  SteamOS-style gamescope session
  webos-session --safe       Hyprland with the rice disabled (debugging)

Session environment: Wayland, XDG_CURRENT_DESKTOP=Hyprland, Breeze_Light
cursor, dark GTK/Qt defaults. GPU hints are set only when the hardware is
unambiguous (NVIDIA or AMD); Intel uses Mesa's auto-detection.

HYPRLAND
--------
Config: ~/.config/hypr/hyprland.lua (source of truth:
/usr/share/webos/rice/hypr/). Hyprland 0.57 reads Lua configuration and
ignores hyprland.conf. webos-rice never overwrites a file you edited unless
you pass --force; edits are tracked by hash in the rice manifest. Put local
changes in ~/.config/hypr/local.lua — hyprland.lua loads it if it exists.

Autostart (`hl.on("hyprland.start")`): dbus activation environment,
`webos-rice --ensure`, `webos-autostart hyprland` (portals + polkit + bar/shell
+ wallpaper + hypridle + hyprsunset), nm-applet, blueman-applet, cliphist
watchers, Breeze_Light cursor, dark GTK defaults.

TERMINAL / SHELLS / FASTFETCH
-----------------------------
kitty and foot run /usr/bin/webos-shell, which prints the WebOS fastfetch card
once (WEBOS_FASTFETCH_SHOWN) and then execs $SHELL. bash, zsh and fish print
the same card on interactive login. Manual: `webos-fastfetch`.
Config: /usr/share/webos/rice/fastfetch/ (fastfetch.json, webos.txt).
Logo: text cobweb (no ImageMagick/chafa needed).
Modules: display, uptime, cpu, gpu, terminal, memory, disk, packages, shell,
datetime.
Theme: pure black, monochrome, thin white bar cursor, white selection.
Failures are logged to /tmp/webos-fastfetch.log.

GAMING / PERFORMANCE
--------------------
- zram swap: RAM/2 capped at 8 GiB, zstd, priority 100 (local.d webos.start).
- sysctl tuning: vm.swappiness=100, vfs_cache_pressure=50,
  vm.max_map_count=2147483642, split_lock_mitigate=0, netdev_max_backlog.
- gamemode, MangoHud, gamescope, vkBasalt, vkd3d-proton, Lutris, Heroic.
- `webos-gaming status`            what is running and with what
  `webos-gaming gamescope [cmd…]` run a command in gamescope
  `webos-gaming gamescope-session` SteamOS-style session
  `webos-gaming mangohud-toggle`  flip MangoHud
  `webos-gaming proton install|list` fetch/list Proton-GE
  `webos-gaming tune <profile>`   apply an scx/CPU profile
  `webos-gaming bench <cmd…>`     run with MangoHud + logging
- Steam and 32-bit Windows games need multilib. Options: Flatpak Steam
  (recommended), Distrobox, or a future multilib WebOS build. If selected,
  the installer writes /etc/webos/steam-unavailable.txt.
- NVIDIA: x11-drivers/nvidia-drivers is installed; nouveau is blacklisted.
  Choosing NVIDIA in the installer adds nvidia-drm.modeset=1 and dracut
  force_drivers. AMD/Intel systems ignore it.

UPDATES / PACKAGES
------------------
Portage + OpenRC. No binary host by default: emerge compiles from source.
Repos: gentoo, webos (local overlay /usr/local/portage/webos); build-only
overlays may be disabled under /etc/portage/repos.conf.disabled.

  sudo webos-update              refresh WebOS overlay, sync repos, rebuild
                                 @world, depclean, config, kernel + GRUB,
                                 Flatpak, rice; log /var/log/webos-update.log
  sudo webos-update --check      show what would change
  sudo webos-update --yes        non-interactive config merges
  --no-sync | --no-flatpak | --no-depclean | --no-kernel | --quiet

  You do NOT have to update the kernel or software by hand. webos-update first
  refreshes the local WebOS overlay from GitHub (auto-sync=no, so emerge --sync
  alone would never see new WebOS ebuilds), rebuilds @world, and explicitly
  updates sys-kernel/webos-kernel (it is not in @world). It regenerates
  /boot/grub/grub.cfg when a new kernel image lands and tells you to reboot.
  Kernel security fixes are shipped as a new ebuild revision in the WebOS repo;
  one `webos-update` on each machine picks them up. Manual Portage commands
  remain available below.

  sudo emerge --sync
  sudo emerge -av <package>
  sudo emerge -avuDN @world
  sudo emerge --depclean
  sudo dispatch-conf

TROUBLESHOOTING
---------------
- Rice missing/odd: `webos-rice --user --force`, then log out and in.
- No waybar: `webos-rice --toggle-panel` or run `waybar`; check
  `webos-rice --doctor` and /tmp/webos-autostart.log.
- fastfetch blank: run `webos-fastfetch`; read /tmp/webos-fastfetch.log.
  Remove WEBOS_FASTFETCH_SHOWN to force it in the current shell.
- No polkit prompt: check /tmp/webos-portals.log and that
  /usr/libexec/dbus-daemon-launch-helper is 4754 root:messagebus; restart
  the session or run `webos-portals`.
- Hyprland starts with no bar/autostart: check
  ~/.config/hypr/hyprland.lua exists and starts with the WebOS header (not
  the upstream example), run `webos-rice --doctor`, and look at
  /tmp/webos-autostart.log. `webos-rice --user --force` restores it.
- More than one session in SDDM: the greeter lists /usr/share/webos/sessions,
  which the installer fills with only the chosen profile. A second entry means
  a stale .desktop was left in that directory; remove it and check
  /etc/sddm.conf.d/20-webos-session.conf. Plasma should not be there unless
  the Plasma profile was chosen.
- No sound: `rc-service elogind status`, `pavucontrol`; PipeWire runs per
  user (wireplumber).
- Installer log: /var/log/webos-install.log; install config
  /etc/webos/install.toml.
- Hyprland log: ~/.local/share/hyprland/hyprland.log.

KNOWN LIMITATIONS / NOTES
-------------------------
- 64-bit only image: no Wine, native Steam, winetricks, protontricks or
  goverlay. Use Flatpak Steam or Distrobox.
- regular Plasma 6.8.3 (opt-in profile) is Wayland-only here (no startplasma-x11).
- /usr/share/xsessions/Xsession.desktop is the standard xinit entry; SDDM
  does not offer it because WebOS points SessionDir at
  /usr/share/webos/sessions.
- No binary package host by default; updates compile from source.
- GitHub social preview cannot be set from the CLI.
