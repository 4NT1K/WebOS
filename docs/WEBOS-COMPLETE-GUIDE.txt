PURPOSE OF THIS FILE
--------------------
This is the single deep-context brief for the WebOS project. If you are handed
the source checkout on a working WebOS machine, read this first. It explains
what the distro is, where everything lives, which files are contract-sensitive,
how the build and release pipeline works, what has already been fixed, what is
still pending, and what future work (including a possible KDE Plasma X11
addition) would touch.

It is intentionally plain text so it can be read from a shell, a USB stick, or
an installed machine without Markdown tooling. For shorter summaries see
README.md, STATUS.md, docs/ARCHITECTURE.md, docs/BUILD.md and docs/RELEASE.md.
For the shipped end-user/system brief see overlay/webos-theme/webos-theme/files/
WEBOS-INFO.txt (installed as /usr/share/webos/WEBOS-INFO.txt).

0. CURRENT STATE AND GROUND RULES
================================================================================

Identity
  Name:            WebOS
  Codename:        Ashen
  Version:         1.02 (marketing version from branding/version)
  Full version:    1.02-Ashen
  ID:              webos
  Kernel:          6.12.0-webos (vanilla LTS + WebOS config fragment)
  Init:            OpenRC + elogind (no systemd)
  Desktop:         Hyprland (Wayland) with the Ashen greyscale rice
  Greeter:         SDDM
  Arch:            amd64 (ABI_X86="64", x86-64-v3 baseline)
  ISO:             webos-1.02-Ashen-amd64.iso
  Upstream:        https://github.com/4NT1K/WebOS
  Maintainer acct: 4NT1K

Release state at the time this guide was written
  - v1.02 source is frozen, committed and pushed to origin/main at 49829b6;
    documentation-only follow-up at 668079b.
  - v1.01 is historical; do not overwrite/republish it.
  - The regression gate scripts/50-check.sh passes with 0 problems (206 checks).
  - Rootfs rebuild was in progress; ISO build, Ventoy copy and GitHub v1.02
    publication were the remaining release steps. Check STATUS.md for live state.

Hard constraints (NEVER violate these)
  1. Binary-first Portage via --getbinpkg and the Gentoo x86-64-v3 binhost.
  2. NEVER use -G, -K, --getbinpkgonly or --binpkg-respect-use=n.
     --fast uses --binpkg-changed-deps=n plus --binpkg-respect-use=y.
  3. Power actions are loginctl-only. The Waybar power widget glyph is exactly
     ⏻ , tooltip exactly:
     "Power — open session menu (reboot, shut down, suspend)"
     and on-click is exactly "wlogout".
  4. Stats must show real RAM used/total and every CPU core as "c0 2% 53C".
  5. Music dropdown: compact 340x340 square, lightly frosted Spotify cover,
     spinning vinyl with the cover as its centre label, pure black/white text,
     flat outline-free buttons and bars, bold top-left title/artist (long
     titles wrap to two lines instead of being cut off), elapsed/total
     progress bar with flat controls beneath it, a slim outline-free Spotify
     volume fader on the right edge, outside-click dismissal, and
     GtkLayerShell-0.1 before 1.0. Dragging the seek previews it and seeks on
     release; volume applies continuously while dragging. The Waybar pill is
     centred on its own and shows only icon/title/artist, never track time.
     No audio visualizer is installed.
  6. Installed systems receive features through `sudo webos-update`; overlay
     main must be pushed BEFORE building/publishing an ISO.
  7. Desktop notifications use ./scripts/notify-user.sh "<message>" "WebOS Release".
  8. Never shut the machine down as part of a release. Leave it powered on.

If you change a contract-sensitive file, update scripts/50-check.sh and rerun it.

  Console/login banners; both carry 1.02.

branding/logo.svg, webos-logo.png, webos-logo-512.png, wallpaper.png
  Artwork. The rice uses /usr/share/webos/logo.svg (the 512x512 cobweb mark),
  NOT the wallpaper SVG, which is a black rectangle and made hyprlock/KDE About
  draw an invisible square.

config/make.conf
  Shipped /etc/portage/make.conf. x86-64-v3 COMMON_FLAGS/CFLAGS/CXXFLAGS and
  RUSTFLAGS, MAKEOPTS=-j16 -l24, EMERGE_DEFAULT_OPTS includes --getbinpkg,
  FEATURES with parallel-fetch/parallel-install/split-log, gaming USE flags,
  CPU_FLAGS_X86 without AVX-512 (stale AVX-512 caused NumPy SIGILL in waypaper),
  ABI_X86="64", ACCEPT_KEYWORDS="~amd64", WEBOS_OS/WEBOS_VERSION markers.
  This file must not contain forbidden binary flags.

config/binrepos.conf/gentoo.conf
  Pins https://distfiles.gentoo.org/releases/amd64/binpackages/23.0/x86-64-v3
  at /var/cache/binhost/gentoo with verify-signature=true.

config/repos.conf/{gentoo,webos,guru,hyproverlay,steam-overlay}.conf
  Repository priorities: webos(100) > gentoo(-1000) > third-party(-2000).
  The WebOS overlay is a local repo at /usr/local/portage/webos with
  auto-sync=no; that is why webos-update refetches it from GitHub main.

config/sets/{base,desktop,gaming,plasma,webos-installer}
  Build-time @sets mirrored by metapackages. @plasma is opt-in only.

config/world
  Base world file installed into the chroot.

config/package.use/{00-global,gaming}
  Per-package USE tuning, e.g. kde-frameworks/kconfig-6.32.0 qml.
config/package.mask/00-webos
  Masks systemd and unwanted packages.
config/package.accept_keywords/{00-webos,webos}
  Testing keywords for fast-moving desktop/gaming packages.
config/package.license/00-webos
  License policy.
config/env/*
  Package-specific environment (ananicy-cpp, nss-mdns).

overlay/profiles/default/linux/{amd64,arm64}/webos/

4. INSTALLER (Rust crate)
================================================================================

Location: installer/ (crate webos-installer, version 1.0.0)
Build:    make -C installer release  (or installer/target/release/webos-installer)
Deps:     vendored in installer/vendor/; installer/.cargo enforces offline.
Offline:  ebuild builds with CARGO_NET_OFFLINE=true, --locked.

Source map
  installer/src/main.rs        argument parsing, terminal setup, event loop
  installer/src/app.rs         wizard state, key handling, install worker thread;
                               INSTALL_STAGES (13 labels) and stage-count logic
  installer/src/ui.rs          ratatui rendering (pure functions of App)
  installer/src/gui.rs         windowed/egui installer front-end
  installer/src/theme.rs       Ashen palette for ratatui + egui; progress colours
  installer/src/config.rs      InstallConfig, Profile enum, validation
  installer/src/disk.rs        disk enumeration, firmware detection, partitions
  installer/src/rootfs.rs      locate/mount the system to install
  installer/src/install.rs     the install recipe and generated chroot script
  installer/src/bootloader.rs  GRUB install and kernel command line
  installer/src/exec.rs        command runner, logging, UI progress reporting

Profiles (installer/src/config.rs)
  Full    = "WebOS — Hyprland + gaming" (default)
  Plasma  = "KDE Plasma + gaming" (currently Wayland)
  Minimal = minimal/no desktop
  Profile chooses the SDDM session .desktop name: webos.desktop for Full,
  plasma.desktop for Plasma. The installer links only that session into
  /usr/share/webos/sessions/{wayland,x11}, so SDDM shows one option. Both
  session directories and SDDM [Wayland]/[X11] SessionDir settings are already
  created in install.rs, which matters for the possible X11 work in §14.

13 truthful stages (installer/src/app.rs)
  Preparing, Partitioning, Encrypting, Creating filesystems, Mounting,
  Fixing filesystem ownership, Copying the system, Writing /etc/fstab,
  Configuring the system, Building the initramfs, Installing the bootloader,
  Recording the install, Unmounting.
  Stage count subtracts one when Encryption::None. The label order matches the
  actual r.phase(...) emission order; do not reorder it to match an older idea.

Install recipe highlights (installer/src/install.rs)
  - rsync -aHAX --numeric-ids --one-file-system with pseudofs exclusions;
    setuid/setgid preserved (no recursive chown that strips bits).
  - btrfs subvolumes @ @home @snapshots @cache @log @tmp, zstd:1 mount options.
  - rootflags=subvol=@ is mandatory in GRUB for btrfs.
  - Optional LUKS2 opened as webos_crypt; dracut adds crypt/dm/btrfs modules.
  - User groups ensured: wheel,audio,video,render,input,plugdev,gamemode,usb,kvm,seat.
  - 32-char /etc/machine-id and /var/lib/dbus/machine-id symlink verified.
  - Live glue removed: /etc/inittab.webos-orig restored; /etc/webos-live deleted.
  - Gaming toggle off removes webos-gaming packages plus wine/protontricks/
    vkd3d/tools and writes /etc/webos/gaming-not-installed.txt.
  - Steam wording is honest: "Steam (Flatpak fallback)" in app.rs,
    "Steam as a Flatpak fallback" in config.rs; Flatpak fallback recorded in
    install.rs. Native Steam is impossible with ABI_X86=64.
  - Non-Plasma profiles unmerge Plasma packages except the keep-list
    {systemsettings, breeze}, remove plasma.desktop, and install qt6ct/breeze/
    konsole. Plasma profile emerges @plasma and removes qt6ct (conflict).
  - Assertions fail loudly if Plasma presence does not match the chosen profile.

Installer ebuild
  overlay/app-admin/webos-installer/webos-installer-1.0.0.ebuild
  Manifest + metadata.xml present. Installer tarball is staged before emerge.

5. KERNEL
================================================================================

kernel/patchset.conf
  Pipe-delimited name|url|sha256|target-series|description. Entries with sha256
  "auto" are pinned in place on first fetch; an existing pin mismatch is fatal.
  For 6.12 all patch entries are commented out (upstream URLs unavailable), so
  the image ships stock LTS + the WebOS fragment. CONFIG_SCHED_BORE and
  CONFIG_TCP_CONG_BBR3 in the fragment are harmless if the tree lacks them.

kernel/fetch-patches.sh
  Downloads and verifies patches into build/cache/kernel-patches/ with series,
  INDEX and .lock. --verify rechecks pins without downloading.

kernel/webos-fragment.config -> overlay/sys-kernel/webos-kernel/files/webos-fragment.config
  Symlink; the fragment lives with the ebuild that consumes it.
  Sets CONFIG_LOCALVERSION="-webos", CONFIG_HZ=1000, CONFIG_PREEMPT_DYNAMIC=y,
  CONFIG_SCHED_CLASS_EXT=y, CONFIG_SCHED_BORE=y, desktop/gaming knobs.

overlay/eclass/webos-kernel.eclass
  webos_apply_patchset, webos_merge_config (strict CONFIG_* replacement),
  webos_kernel_make, webos_kernel_release, webos_kernel_install.

overlay/sys-kernel/webos-kernel/webos-kernel-6.12.ebuild
  Builds/installs vmlinuz, modules and a header tree; writes a fragment stamp
  via newins to /boot/webos-fragment.sha256 so scripts/20-kernel.sh can detect
  config changes and rebuild deterministically. Do not replace newins with a
  raw ${ED}/boot write.

overlay/sys-kernel/webos-kernel-sources/webos-kernel-sources-6.12.ebuild
  Ships patched tree under /usr/src/linux-<PV> plus the fragment.

overlay/virtual/linux-sources/linux-sources-3-r9.ebuild
  Virtual provider; we do not use dist-kernels.

scripts/20-kernel.sh
  Refreshes overlay in chroot, drops patch series into /var/cache/webos/patches,
  runs egencache, regenerates kernel Manifests, emerges sources + kernel, writes
  build/.kernel-release.

6. LIVE MEDIUM / ISO
================================================================================

livecd/boot/grub/grub.cfg
  GRUB template for the hybrid BIOS+UEFI image. @VOLID@ and @VERSION_FULL@
  are substituted by scripts/40-iso.sh.

livecd/etc/conf.d/agetty.tty1
livecd/etc/profile.d/99-webos-live.sh
livecd/etc/webos-live
livecd/usr/local/bin/webos-live-session
  Live root autologin and menu. Both agetty and sysvinit /etc/inittab paths are
  covered; inittab is backed up as /etc/inittab.webos-orig.
  Safety: live glue checks for /etc/webos-live so it can never take over an
  installed system. The installer removes the marker and restores inittab.

scripts/40-iso.sh
  1. kernel -> /boot/vmlinuz-webos
  2. dracut initramfs with dmsquash-live + pollcdrom
  3. build/live-root = build/rootfs + livecd/
  4. mksquashfs zstd, 1 MiB blocks -> /live/webos.squashfs
  5. writes /webos/version, substitutes GRUB template variables
  6. grub-mkrescue -> build/webos-1.02-Ashen-amd64.iso + .sha256
  It normalizes ownership without stripping setuid/setgid bits.

Boot flow (live)
  firmware -> GRUB -> vmlinuz-webos + initramfs -> dmsquash-live mounts
  /live/webos.squashfs at /run/initramfs/live -> OpenRC -> tty1 root autologin
  -> webos-live-session -> webos-installer.

Boot flow (installed)
  firmware -> GRUB -> vmlinuz-6.12.0-webos -> root=UUID=... [LUKS]
  rootflags=subvol=@ -> OpenRC -> SDDM -> webos-session -> Hyprland.

9. DESKTOP CONTRACT - RICE, POWER, NOTIFICATIONS, STATS, MUSIC

Hyprland config
  Hyprland 0.57 reads ~/.config/hypr/hyprland.lua and ignores hyprland.conf.
  hyprland.conf was removed; hyprland.lua + webos-colors.lua are authoritative.
  Key highlights: Super+Q kitty, Super+Shift+Return foot, Super+C close,

Power (contract-sensitive)
  Waybar right modules end in custom/power in BOTH rice and mono profiles.
  Exact glyph: ⏻
  Exact tooltip: Power — open session menu (reboot, shut down, suspend)
  Exact on-click: wlogout
  wlogout/layout uses loginctl suspend/hibernate/reboot/poweroff only.
  ipc:false is set in both Waybar configs so IPC cannot corrupt the widget.
  #custom-power styled in both CSS files.

Lock/idle
  hypridle lock_cmd: hyprlock --grace 0 --no-fade-in
  DPMS off/on: hyprctl eval 'hl.dispatch(hl.dsp.dpms({ action = "off"/"on" }))'
  Dim: only if /sys/class/backlight exists, and brightnessctl -c backlight.
  hyprlock Pango colour uses ##7A7A7A; obsolete grace/no_fade_in keys removed.

Legacy migration
  webos-rice migrate_legacy_waybar() detects the known old mono config hash,
  backs it up once with .webos-orig, then writes the new config with the power
  widget. User edits are never silently destroyed.

Notifications
  Use scripts/notify-user.sh, not ad-hoc notify-send. Sound fallback included.

Stats
  webos-stats shows actual RAM used/total (not cached math) and every CPU core
  with usage and temp like "c0 2% 53C". Thermal fallback via thermal_temp().

Music
  webos-music is a 340x340 GTK layer-shell square under the bar. Spotify cover
  art is lightly frosted (blur 2.5, full brightness) and also becomes the
  rotating label of a Cairo-drawn vinyl. art_is_light() picks pure black or
  white text, buttons and bars; no glows, outlines or button boxes.
  Playback buttons sit under the elapsed/total bar and a slim vertical
  volume fader on the right edge applies changes live while dragging. The Waybar spectrum only
  appears while Spotify plays. The Waybar pill lists only title and
  artist. Outside clicks are dismissed by a full-screen transparent catcher.
  GtkLayerShell 0.1 is requested before 1.0.

10. UPDATER AND DELIVERY TO INSTALLED SYSTEMS
================================================================================

overlay/webos-theme/webos-theme/files/system/webos-update (installed /usr/bin/webos-update)
  VERSION=1.02, log /var/log/webos-update.log.
  Steps:
    [0/8] --no-compile preflight (pretend with --getbinpkg; abort if source builds)
    [1/8] sync repos + refresh WebOS overlay from GitHub main tarball
    [2/8] @world update (dry run for --check), reports binpkg vs source counts
    [3/8] config file updates
    [4/8] depclean (retired Vesktop entries also removed from custom sets)
    [5/8] Flatpak update
    [6/8] re-apply rice
    [7/8] kernel + GRUB
    [8/8] health check and reboot recommendation ("reboot with: loginctl reboot")

Flags:
  --check             dry run only
  --fast/--fast-binpkg adds --binpkg-changed-deps=n, keeps --binpkg-respect-use=y
  --strict-use/--respect-use adds --binpkg-respect-use=y --binpkg-changed-deps=y
  --buildpkg          cache source builds locally
  --no-compile        abort before any change if a source build is needed
  --yes, --no-sync, --no-flatpak, --no-depclean, --no-kernel, --quiet

Forbidden flags must never appear: -G, -K, --getbinpkgonly,
--binpkg-respect-use=n. If a stock binpkg's USE flags do not match, Portage
falls back to source (allowed), or --no-compile stops cleanly. We do not force
binary-only because that would reinstall hundreds of packages.

Delivery path
  Commit/push source to origin/main first. webos-update downloads
  https://github.com/4NT1K/WebOS/archive/refs/heads/main.tar.gz and replaces
  /usr/local/portage/webos. The current theme revision then reaches installed systems
  on their next `sudo webos-update`. r1 stayed historical; remote r2/r3 are
  harmless. Rootfs pins r51 via scripts/30-rootfs.sh.

Release gate for binary-first behavior
  /home/brah/release-v102.sh runs `webos-update --check` and
  `webos-update --fast --check` inside the rebuilt chroot, rejects dependency
  errors and reports binary/source plan counts. Source fallback is allowed by
  design; `webos-update --no-compile` is the user-facing way to refuse it.

13. COMMON FAILURE MODES AND HOW TO AVOID THEM
================================================================================

- Forbidden Portage flags: a single --binpkg-respect-use=n or --getbinpkgonly
  in make.conf/webos-update/docs breaks the contract. Sweep before committing.
- Reusing stale stage labels: INSTALL_STAGES must match r.phase() order.
- Same-version theme edits not reaching rootfs: scripts/30-rootfs.sh unmerges
  then remerges webos-theme and pins r51.
- chroot copy failing with "Directory not empty": a previous cp -a was killed
  mid-copy. Remove the partial build/chroot from inside webos-build and copy
  chroot.backup again; do not try to merge trees.
- Stale rc file: build/v102-rootfs.rc can be older than the running build;
  compare mtimes and check the process/log before declaring failure.
- hyprlock Pango colours: '#' must be '##' or the config fails to parse.
- DPMS: use Lua hl.dispatch(hl.dsp.dpms(...)) with hyprland 0.57; old
  `hyprctl dispatch dpms` is wrong.
- Backlight dim: plain brightnessctl -s set dims keyboard LEDs; use
  brightnessctl -c backlight guarded by /sys/class/backlight.
- AVX-512 in CPU_FLAGS_X86 causes NumPy to emit AVX-512 and waypaper to SIGILL
  on the target Ryzen 5 5600X. Keep the v3 flag list.
- Native Steam: impossible with ABI_X86=64; keep the Flatpak fallback wording.
- Manifest digests: EBUILD/MISC lines must be 128-hex-char BLAKE2B/SHA512.
- Watchers: never add git push or hard-coded /home/brah paths.
- Notifications: use notify-user.sh; do not invent another mechanism.
- Do not shut down. Seriously.

14. FUTURE WORK: POSSIBLE KDE PLASMA X11 ADDITION
================================================================================

Current Plasma situation
  - Plasma is opt-in via the installer's Profile::Plasma, currently described
    as "KDE Plasma (Wayland)" in installer/src/config.rs.
  - config/sets/plasma contains plasma-meta, plasma-workspace, plasma-desktop.
  - It is deliberately outside @desktop. Non-Plasma installs unmerge Plasma
    packages except the {systemsettings, breeze} keep-list and remove
    plasma.desktop; an assertion enforces this.
  - SDDM already has both session directories configured in install.rs:
    /usr/share/webos/sessions/wayland and /usr/share/webos/sessions/x11, with
    [Wayland] and [X11] SessionDir entries. This is the natural hook for X11.
  - webos-plasma-setup applies the DeepBlack colour scheme, cursor and
    wallpaper in Plasma; it is session-type agnostic.
  - The global USE line already has X for XWayland/games; a Plasma X11 session
    still needs Xorg and X11-specific Plasma packages.

What an X11 Plasma variant would touch
  1. installer/src/config.rs
     - Add a Profile::PlasmaX11 (or a session-type flag on Plasma) with label
       "KDE Plasma (X11) + gaming", description, and session name
       plasma.desktop from /usr/share/xsessions instead of wayland-sessions.
     - Keep Profile::ALL consistent and update the Full/Plasma/Minimal cycle.
  2. installer/src/install.rs
     - Generalize the Plasma branch: link the chosen session into
       /usr/share/webos/sessions/x11 for X11, wayland for Wayland. The generic
       session-link block already handles xsessions fallback; make the Plasma
       post-install link use the same helper.
     - Update the Plasma assertion to check wayland/plasma.desktop OR
       x11/plasma.desktop according to the selected profile.
     - Non-Plasma cleanup must still remove both wayland and x11 plasma entries.
     - Optionally set /etc/sddm.conf.d/20-webos-session.conf DisplayServer=x11
       for the X11 profile, or leave SDDM auto if both session dirs are desiring.
  3. config/sets/
     - Add config/sets/plasma-x11 (or extend @plasma with a USE-controlled X11
       subgroup) with x11-base/xorg-server, x11-drivers/xf86-input-libinput,
       x11-apps/setxkbmap/xrandr, and any kde-plasma/* X11 session dependencies.
     - Keep it out of @desktop so the default Hyprland image stays lean.
  4. overlay/webos-desktop/webos-desktop/
     - Either add a plasma USE flag to the metapackage or create a separate
       webos-plasma metapackage; do not make Plasma a default RDEPEND.
  5. overlay/webos-theme/webos-theme/files/system/webos-plasma-setup
     - Reuse as-is; verify DeepBlack applies under X11 KWin too.
     - Ensure xdg-desktop-portal-kde and polkit are present for X11.
  6. Portage/USE
     - Global X is already enabled. Check kde-plasma/plasma-workspace,
       kde-plasma/plasma-desktop and Qt USE flags for X/xcb requirements.
     - Continue using --getbinpkg with the v3 binhost; never add forbidden
       flags to make the new profile install faster.
  7. Regression gates
     - Extend scripts/50-check.sh with X11 Plasma assertions: new set file,
       installer profile label, x11 session dir handling, and a check that
       default/non-Plasma profiles still remove x11/plasma.desktop.
     - Extend /home/brah/release-v102.sh-style runtime gates to smoke-test
       SDDM -> Plasma X11 -> webos-plasma-setup, then confirm the Full profile
       still boots Hyprland.
  8. Docs/release notes
     - Update docs/ARCHITECTURE.md, installer/src/config.rs descriptions,
       README.md, ROADMAP.md, WEBOS-INFO.txt and future release notes. Make it
       explicit that Wayland/Hyprland remains the default and X11 Plasma is an
       alternative, not a replacement.
  9. Risks
     - More packages and storage; X11 libs plus Plasma can add GBs.
     - Two session stacks means more QA: GPU drivers, SDDM, portals, screenshot
       and gamescope interaction all need testing on both.
     - Keep the greeter showing exactly one session per installed profile; do
       not let both plasma.desktop files leak into the WebOS session dirs.
     - Do not regress the loginctl-only power contract or the ⏻ widget when
       touching SDDM/wlogout/layout.

Storage/compression follow-up (hypothetical, no changes made)
  - Strip debug symbols, drop dev headers/static libs, prune docs/locales/man.
  - Depclean unused packages and old kernels; Flatpak runtimes are large.
  - Rust installer already uses opt-level="z", LTO, panic="abort", stripped.
  - mksquashfs zstd ratio/blocks and btrfs zstd can be tuned; dedupe with
    duperemove before squashfs. Any USE change must be checked against the
