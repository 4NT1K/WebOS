WEBOS 1.034 "ASHEN" - MAINTENANCE / UPDATE HANDOFF
================================================================================

Audience: a future AI assistant (or the maintainer) tasked with changing the
installer, shipping updates, or cutting a release. Read this before editing.

--------------------------------------------------------------------------------
0. CRITICAL NAMING FACT - READ FIRST
--------------------------------------------------------------------------------
The kernel package is named webos-kernel.

  Current and correct names:
    sys-kernel/webos-kernel
    sys-kernel/webos-kernel-sources
    kernel release string: 6.12.119-webos
    installed image:      /boot/vmlinuz-6.12.119-webos
    installed modules:    /usr/src/linux-6.12 (source dir)

  The old pre-rebrand kernel package names are retained ONLY in the
  legacy-cleanup lines in scripts/20-kernel.sh and scripts/30-rootfs.sh, whose
  JOB is to unmerge stale packages from a reused build chroot. They must keep
  the old spelling or the cleanup breaks and the new kernel hits a file
  collision on /boot/vmlinuz-* and /usr/src/linux-6.12. Those strings are
  build-time only and are never installed in the ISO.

  There is no package called "web-kernel" either. It is webos-kernel.

  A clean build has zero legacy pre-rebrand packages installed. The shipped
  ISO, overlay, installer source, branding and config contain no references
  to the old product name.

2. THE TWO UPDATE CHANNELS
--------------------------------------------------------------------------------
Everything hinges on this distinction.

  CHANNEL A - reaches installed machines through `sudo webos-update`
  ---------------------------------------------------------------
  `webos-update` first downloads the latest overlay tarball from
  https://github.com/ugss96/WebOS/archive/refs/heads/main.tar.gz and swaps it
  into /usr/local/portage/webos (the local repo is auto-sync = no, so plain
  `emerge --sync` never sees new WebOS ebuilds). It then rebuilds @world,
  explicitly emerges sys-kernel/webos-kernel (NOT in @world), regenerates GRUB
  when a new /boot/vmlinuz-* appears, and re-applies the rice.

  RULE: any change under overlay/ reaches users this way, but ONLY after you
  bump the relevant ebuild revision AND push to main. Same-version ebuild edits
  are invisible to Portage.

  CHANNEL B - requires a NEW ISO (existing installs cannot receive these)
  ---------------------------------------------------------------------
  installer/, config/, branding/, livecd/, scripts/. The installer is packaged
  into the live medium and deliberately unmerged from the target rootfs
  (scripts/30-rootfs.sh), so installer fixes only matter in a fresh ISO.

--------------------------------------------------------------------------------
3. WHERE TO EDIT WHAT (CHANNEL A)
--------------------------------------------------------------------------------
  Keybinds, waybar modules/CSS, fastfetch card, hyprland rules, transparency,
  zram boot glue, SDDM seeding, WEBOS-INFO.txt
      -> overlay/webos-theme/webos-theme/files/
      -> bump the theme ebuild revision (currently webos-theme-1.0-r53;
         next webos-theme-1.0-r54), regenerate Manifest if files changed.

  webos-update, webos-rice, webos-fastfetch, system helpers
      -> overlay/webos-theme/webos-theme/files/system/
      -> same webos-theme revision bump.

  Kernel security fix / config fragment change
      -> overlay/sys-kernel/webos-kernel/ and webos-kernel-sources/
      -> add patched sources/patch, bump ebuild revision (e.g. 6.12-r1),
         regenerate Manifest with `ebuild ... manifest`.
      -> fragment lives at files/webos-fragment.config (symlinked from
         kernel/webos-fragment.config). Verify the built kernel has
         CONFIG_ZRAM_BACKEND_ZSTD=y and CONFIG_ZRAM_DEF_COMP="zstd".
      -> NOTE: the kernel is not in @world; webos-update emerges it explicitly.

  New WebOS-only application
      -> new directory under overlay/, add to the appropriate config/ set for
         fresh installs, commit, push.

  Ordinary app updates (Firefox, gaming stack, etc.)
      -> nothing to do. Gentoo's repo supplies ebuilds; webos-update compiles.

--------------------------------------------------------------------------------
4. WHERE TO EDIT WHAT (CHANNEL B - NEW ISO REQUIRED)
--------------------------------------------------------------------------------
  Installer UI, progress bar, SDDM session logic, disk code
      -> installer/src/*.rs  (install.rs, app.rs, exec.rs, disk.rs, ...)
      -> bump installer/Cargo.toml version (currently 1.0.0) when changed.

  Default app sets, profile, desktop/plasma profiles
      -> config/sets/desktop , config/sets/plasma , config/

  Version, os-release, issue, logos
      -> branding/version (single source of truth), then config/make.conf,
         overlay/webos-theme/webos-theme/files/WEBOS-INFO.txt, docs.

  Live environment, GRUB, squashfs, initramfs
      -> livecd/ and scripts/40-iso.sh

  Build pipeline itself
      -> scripts/00-fetch.sh ... 50-check.sh

--------------------------------------------------------------------------------
5. STANDARD WORKFLOW
--------------------------------------------------------------------------------
  a) Make the edit in the source tree.

  b) Validate BEFORE committing:
       cd installer && cargo check --offline && cd ..
       bash -n scripts/*.sh overlay/webos-theme/webos-theme/files/system/*
       ./scripts/50-check.sh                       # must print 0 problem(s)
       # for rice/keybind edits, on a test install:
       webos-rice --doctor
       hyprctl binds

  c) Commit and push to main:
       git add -A && git commit -m "..." && git push origin HEAD

  d) For Channel A changes, on the target machine: sudo webos-update
     (it pulls main, so push first). Check /var/log/webos-update.log.

  e) For Channel B changes, rebuild inside the container:
       docker exec -w /webos webos-build ./build.sh rootfs
       docker exec -w /webos webos-build ./build.sh iso
     or the full pipeline: ./build.sh all
     Stages: fetch, bootstrap, kernel, rootfs, iso. Output is
     build/webos-1.034-Ashen-amd64.iso.

--------------------------------------------------------------------------------
6. CUTTING A NEW RELEASE VERSION
--------------------------------------------------------------------------------
  Follow docs/RELEASE.md. Short version:
    1. Bump branding/version (WEBOS_VERSION, WEBOS_VERSION_FULL, etc.).
    2. Update WEBOS-INFO.txt, README.md, STATUS.md, and write
       docs/releases/vX.md.
    3. Build + run scripts/50-check.sh + smoke-test the ISO.
    4. Compute SHA256, split the ISO into parts, write SHA256SUMS.txt + README.txt.
    5. Tag and publish on GitHub with gh release create vX --title ... --notes ...
       mark it Latest.
  Full checklist: docs/RELEASE.md sections 1-11. Section 11 documents shipping
  kernel security updates to already-installed machines.

7. GOTCHAS / THINGS ALREADY FIXED (do not regress)
--------------------------------------------------------------------------------
  * Kernel fragment change needs a forced kernel rebuild; 20-kernel.sh checks
    the installed image against the fragment.
  * Reused chroots must have legacy pre-rebrand kernel packages removed first or
    webos-kernel collides on /boot/vmlinuz-* (fixed in 20-kernel.sh).
  * webos-kernel-sources Manifest BLAKE2B must be HEX, not base64, or Portage
    renames the distfile and unpack fails. webos-kernel/Manifest is fine.
  * Plasma is opt-in (config/sets/plasma). Non-Plasma profiles unmerge it and
    remove plasma.desktop. SDDM must expose exactly ONE session: the one chosen
    in the installer, seeded in /var/lib/sddm/state.conf.
  * Do NOT switch the session to plain Hyprland. The intended command is
    `webos-session`, which starts Hyprland with ~/.config/hypr/hyprland.lua and loads the WebOS
    mono rice. Only reword misleading docs.
  * Keybinds: Super+Q kitty, Super+Shift+Return foot, Super+C close,
    Super+D / Super+R webos-menu, Super+M webos-music --toggle,
    Super+Escape hyprlock, Super+scroll workspaces 1-5,
    Super+Shift+Escape exit, Super+Shift+S webos-shot region,
    Super+Ctrl+S move window to special.
  * Mono waybar: no network or battery module; the cpu, memory and pulseaudio
    pills (and their aliases) are removed. The far-right ⏻ custom/power pill
    opens wlogout. Right cluster is
    ▧ waypaper, clock, tray, ▾ performance, ⏻ power. Music and performance are
    the webos-music / webos-stats dropdowns, toggled from the mpris pill and ▾.
  * Pointer: accel_profile = flat, force_no_accel = true.
  * Kitty owns terminal alpha in BOTH configs (background_opacity 0.82,
    dynamic_background_opacity no, background_blur 24, bold/italic `auto`);
    Hyprland kitty rule is opacity = "1.0 1.0" to avoid multiplied alpha.
  * Installer progress must stay monotonic; completed stages show 100%.
  * webos-rice prunes stale hyprland.conf / webos-colors.conf manifest entries.

--------------------------------------------------------------------------------
8. USER-FACING UPDATE COMMAND (for reference)
--------------------------------------------------------------------------------
  sudo webos-update                 # full update
  sudo webos-update --check         # dry run
  sudo webos-update --yes           # non-interactive config merges
  sudo webos-update --no-sync       # skip repo + overlay refresh (offline)
  sudo webos-update --no-kernel     # skip the kernel step
  sudo webos-update --no-flatpak / --no-depclean / --quiet

  Log: /var/log/webos-update.log
