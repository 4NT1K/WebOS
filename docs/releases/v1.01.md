# 🚀 WebOS 1.01 "Ashen"

The first maintenance rebuild of Ashen. Every fix below was applied and verified
on a live WebOS 1.0 system, then carried into the installer and theme so a fresh
1.01 install starts with the fixes already in place.

> **Base:** Gentoo · OpenRC + elogind · no systemd  
> **Kernel:** `6.12.0-webos` LTS + WebOS tuning  
> **Desktop:** Hyprland + the Ashen mono rice  
> **Installer:** `webos-installer` 1.0.0  
> **Theme:** `webos-theme-1.0-r2`

## 🧩 Defaults, packages and theming

- 🧩 **Flatpak + Flathub, on by default.** `sys-apps/flatpak` is unmasked and in
  the desktop set, and the Flathub remote is added — so Flatpak apps and game
  launchers install the way the documentation always promised.
- 🖱️ **Breeze_Light cursor.** `kde-plasma/breeze` now ships the cursor the rice
  already asked for. It is set for GTK and applied to the live Hyprland session.
- 🧷 **Qt6 theming that loads.** `gui-apps/qt6ct` provides both the Qt6
  platform-theme plugin and the `darker.conf` colour scheme, so Qt6 apps follow
  the Ashen palette.
- ⚙️ **System Settings and text files work.** `kde-plasma/systemsettings` is
  installed for the Hyprland settings menu, and `kde-apps/konsole` is installed
  for KIO's `Terminal=true` handlers — opening a `.txt` file from the GUI no
  longer reports "terminal konsole not found".
- 🖥️ **Plasma stays opt-in.** Plasma 6.8.3 lives only in the opt-in `@plasma`
  set. SDDM links only the `.desktop` file for the profile chosen in the
  installer and records it as the default: one session, nothing extra.

## 🖤 Look and feel

- 🖤 **Greyscale, refined.** `#000000` void base, `#D8D8D8` text, `#E8E8E8`
  soft-white accents and borders, `#7A7A7A` dim, and near-opaque
  `rgba(0,0,0,0.92)` surfaces. Greyscale ANSI runs through kitty, foot and
  Konsole; the last ice-blue tokens are gone.
- ◼️ **Square mako.** Notification corners and icon corners are now radius `0`,
  anchored bottom-right, matching the documented square look.
- 🖼️ **Sharper fastfetch card.** The shipped PNG cobweb is rendered through
  `webos-chafa-logo` as fixed-width symbol art; every row is padded to 16 cells
  so Display, Uptime, Shell and Date line up. The text cobweb remains as an
  automatic fallback when chafa is absent.

> 🧊 **Honest about images:** this fastfetch build has **no native image, kitty
> graphics or sixel support**. The logo is coloured terminal characters from
> chafa — symbol art, not a terminal image.

## 🎛️ New dropdowns and bar widgets

- 🎵 **Dropdown music player.** `webos-music` is a GTK3 layer-shell panel under
  the bar. It shows the current track's MPRIS album art as a darkened greyscale
  background, plus title, artist, PLAYING/PAUSED status, previous/play-pause/next
  controls and a seekable elapsed/total bar. Toggle it with `SUPER+M` or by
  clicking the mpris pill — clicks no longer pause or skip playback.
- ▧ **Waypaper widget.** The pill left of the clock launches `waypaper`
  directly. It works now because of the CPU-flag fix below.
- ▾ **Performance arrow.** `webos-stats` opens a small corner dropdown with
  CPU, GPU, VRAM, RAM, DISK and TEMP bars. GPU/VRAM show `n/a` without
  `nvidia-smi`.
- 🧭 **Curated app menu.** `webos-menu` replaces the raw `wofi --show run/drun`
  launchers for `SUPER+D` / `SUPER+R`, filtering out hidden, terminal-only and
  debugger entries so 2to3 and autoconf stop appearing beside your apps.
- 🧹 **Cleaner right cluster.** `modules-right` is now waypaper, clock, tray,
  performance and ⏻ power; the cpu, memory and pulseaudio pills are gone.

## ⚡ Session fixes that stick

- 🔊 **Audio autostart.** `webos-autostart` brings up PipeWire → WirePlumber →
  pipewire-pulse in that order on every login, giving Spotify and other MPRIS
  clients a real output server.
- 🛡️ **Clean login.** `webos-session` now launches Hyprland through
  `start-hyprland`, and the deprecated `special_scale_factor` options are
  removed — no watchdog warning, no deprecated-config notices.
- 🖥️ **Persistent refresh rate.** `webos-refresh` saves and restores exact
  monitor modes at login and watches live changes from wdisplays/wlr-randr.
  Use `webos-refresh set <rate>` to choose a rate and `webos-refresh status` to
  compare current and saved modes.
- 🧬 **CPU flags fixed for waypaper.** Stale AVX-512 flags were removed from
  `CPU_FLAGS_X86` (the target CPU has AVX2, not AVX-512) and NumPy was rebuilt.
  `waypaper` no longer dies with SIGILL when it imports NumPy through imageio.
- 📸 **Focused-output screenshots.** `webos-shot output` / `Super+Print` now
  passes `-o` for the focused monitor to `grim`; full-screen capture stays
  whole-screen.

## 💿 Download and install

Download the split assets for **`webos-1.01-Ashen-amd64.iso`**: `README.txt`,
`SHA256SUMS.txt`, and `webos-1.01-Ashen-amd64.iso.part-00` through
`webos-1.01-Ashen-amd64.iso.part-02`. Reassemble and verify them in order:

```sh
cat webos-1.01-Ashen-amd64.iso.part-00 \
    webos-1.01-Ashen-amd64.iso.part-01 \
    webos-1.01-Ashen-amd64.iso.part-02 > webos-1.01-Ashen-amd64.iso

sha256sum -c SHA256SUMS.txt
```

Flash the resulting ISO with Ventoy, Rufus, balenaEtcher or `dd`. UEFI is the
recommended path; BIOS is supported. After boot the installer asks for disk,
filesystem, account and features — session seeding, rice, kernel, GRUB and
services are handled for you. ✅

## 🛠️ Post-release fix (same 1.01 build)

Two issues found on a freshly installed 1.01 system were corrected in the
build system and are included in the replacement image:

- 🧬 **waypaper no longer SIGILLs.** NumPy and the other CPU-FLAG-sensitive
  packages (`eigen`, `libgcrypt`, `libde265`, `svt-av1`, `zlib-ng`) are now
  forcibly rebuilt after the AVX-512 flags are removed, so no AVX-512 code
  survives in the image.
- 🗂️ **`webos-update` keeps a valid world file.** The three third-party
  overlays (`guru`, `hyproverlay`, `steam-overlay`) now ship with the image
  instead of being disabled, so packages installed from them stay resolvable
  and `emerge @world` no longer reports `no available ebuilds`. The Plasma
  6.32 `kconfig[qml]` USE flag is preset, and the updater uses deeper
  backtracking for mixed-version dependency graphs.
- 📦 **`webos-update` now prefers prebuilt binaries.** `EMERGE_DEFAULT_OPTS`
  carries `--getbinpkg`, and the Gentoo binhost is pinned to the matching
  `x86-64-v3` tree, so updates use binaries when they match and fall back to
  source otherwise. The updater message, waybar update counter and reboot hint
  are accurate.
- ⏻ **Native power actions.** wlogout/hypridle use `loginctl` verbs exclusively
  (no `systemctl` assumptions), and a new far-right Waybar power widget opens
  the session menu. The `/etc/xdg/waybar` fallback config is replaced with the
  WebOS rice config too, so the stale `systemctl` power menu cannot reappear.
  The mono dotfiles profile now carries the same ⏻ pill, and `webos-rice`
  migrates the older mono config/style on update so existing installs get the
  button back without overwriting genuinely user-edited files.
- 🔒 **Lock-screen placeholder renders correctly.** Hyprlang treats a single
  `#` as a comment marker, which truncated the Pango `foreground` colour and
  showed raw `<span foreground=` markup in the password field. The hex colour
  is now escaped as `##7A7A7A`, so the dim “enter password…” hint displays as
  intended.
- 🔒 **hyprlock starts cleanly.** The removed `general.grace` and
  `general.no_fade_in` options are gone from the config; hypridle now passes
  `--grace 0 --no-fade-in` on the command line instead.
- 🌑 **Idle display blank works again.** Hyprland 0.57's Lua config needs
  `hl.dispatch(hl.dsp.dpms({ action = "off" }))`; the old `hyprctl dispatch
  dpms off` command was a Lua syntax error.
- 💡 **Idle dim no longer touches keyboard LEDs.** The dim rule is scoped to
  the `backlight` device class and guarded so machines without a backlight
  leave their LEDs alone.
- 🤫 **Waybar no longer warns about IPC on every launch.** The unused IPC
  socket is disabled in both the rice and mono configs.
- ⚡ **Binary-first updates.** Portage and `webos-update` now accept stock
  Gentoo binpkgs even when USE flags or dependency sets differ, so updates no
  longer spend an hour compiling LLVM, Clang and KDE. Use `webos-update
  --strict-use` to opt back into exact-USE builds, and `--buildpkg` to cache
  the packages that still need compiling.
- 🛠️ **Installer and build fixes.** The progress counter now includes the
  bootloader phase, the Gaming toggle actually removes gaming-only packages,
  Steam is described honestly as a Flatpak fallback, Manifests use hex BLAKE2B,
  and kernel fragment changes are detected by hash.
- 🎵 **Music dropdown fixed.** The player is now a compact 340x340 square that
  slides down from the bar instead of landing in the middle of the desktop.
  The song cover fills the whole panel as a lightly frosted, recognisable
  background, and a 20-band cava-driven visualizer in the middle takes its
  colours from the cover art and listens only to the active music player (not
  other system audio), with cava's native smoothing. The theme now requires
  gtk-layer-shell introspection and falls back cleanly without it. Both the
  music and performance dropdowns now close when you click outside them.
- 📊 **More detailed performance menu.** RAM now shows actual used/total
  capacity, and every CPU core has its own row with usage and temperature
  (e.g. `c0   2% 53C`).
- 📖 **In-depth system guide ships in the image.** `/usr/share/webos/WEBOS-INFO.txt`
  documents the whole distro (sessions, rice, updates, binpkg rules, logind
  power actions, stats, maintainer/release workflow from WebOS itself) and is
  installed by `webos-theme-1.0-r2` for future releases.

## 📌 Known notes

- 🖼️ Fastfetch logo art is chafa symbols only — no native image, kitty or
  sixel support; the text cobweb is the fallback.
- 🔄 "119.98 Hz" was **one exact test mode** (`1920x1080@119.98`) used to prove
  the watcher saves live changes. It is not a range. The saved default is
  **60 Hz** (`1920x1080@60.00000`), and only advertised `availableModes` can be
  persisted.
- 🖱️ Log out and back in once for the cursor and GTK theme to fully settle.
  Qt5 apps keep toolkit defaults; there is no qt5ct in this Portage tree.
- ⚠️ On an existing install, use plain `webos-rice --user`, not
  `webos-rice --user --force` — the latter overwrites user-edited managed files.
