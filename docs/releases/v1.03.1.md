# WebOS 1.03.1 "Ashen" — kernel security update

> **Superseded by [`v1.03.2`](v1.03.2.md).** The ebuilds in this release pinned
> `linux-6.12.119.tar.xz`, but `kernel-2.eclass` unpacks a three-component
> kernel version as `linux-6.12.tar.xz` + `patch-6.12.119.xz`. Both kernel
> packages failed in `src_unpack`. Do not install from this tag; use `v1.03.2`.

**Release type:** source/overlay update only. The `v1.03` ISO is not replaced.

| | |
|---|---|
| Installed identity | WebOS 1.03 (Ashen) — unchanged |
| Git tag | `v1.03.1` |
| Kernel | `6.12.119-webos` (Linux 6.12 LTS, released 2026-11-23) |
| Delivery | WebOS overlay + `webos-update` |

## Why this exists

The `v1.03` image shipped the plain `linux-6.12` tarball. This update moves
both kernel packages to the current 6.12 longterm tarball,
`linux-6.12.119.tar.xz`, which carries the upstream stable/security fixes
accumulated through 2026-11-23. They include AppArmor policy-unpack failures
and a double free, an `nvmet-auth` out-of-bounds read, `ntfs3` deadlock and
read-only ioctl fixes, an `nvme-tcp` netns use-after-free, a Ceph inode leak,
and BPF/libbpf bounds fixes. No third-party or out-of-tree kernel patch is
added: the WebOS patchset remains empty and the config fragment is unchanged.

## Changes

- `sys-kernel/webos-kernel` and `sys-kernel/webos-kernel-sources` are now
  `6.12.119`; both `SRC_URI` and `S` point at the pinned upstream tarball.
- The installed kernel release string is `6.12.119-webos`.
- `K_SECURITY_UNSUPPORTED` is removed: this build tracks the current 6.12 LTS
  stream instead of advertising itself as likely vulnerable.
- The GCC 16 C11 workaround is narrowed. The decompressor in 6.12.119 already
  sets `-std=gnu11`; the EFI stub still needs it. Both subtrees keep the
  warning suppression.
- The stable `/usr/src/linux-6.12` build-tree path is preserved so NVIDIA and
  other out-of-tree modules keep building after the point release.
- Both `Manifest` files pin the exact tarball and ebuild digests.
- `scripts/50-check.sh` now checks the pinned version across both ebuilds and
  no longer hard-codes a single ebuild filename.

## How to update

```bash
sudo webos-update
sudo reboot
uname -r        # 6.12.119-webos
```

Old kernels stay in the GRUB menu as a fallback. `--no-kernel` skips the
kernel/bootloader step if you need to defer the reboot.

## ISO and identity

There is **no new ISO** for `v1.03.1`. Fresh installs still use the published
`webos-1.03-Ashen-amd64.iso` split parts; `/etc/os-release` and the installer
continue to report `1.03 (Ashen)`. A future ISO built from this tree would
contain the 6.12.119 kernel, but none was rebuilt or published for this patch
release.

## Validation and limitations

- `bash -n`, `git diff --check`, and `bash scripts/50-check.sh` pass on the
  tagged tree. `50-check` also validates the first-party Python helpers;
  `python3 -m py_compile` has no first-party `.py` files to compile (the rest
  are vendored installer sources).
- The tarball digest is pinned from the kernel.org artifact; the repo build
  regenerates both kernel Manifests before emerge.
- No ISO was rebuilt or boot-tested here because this host has no
  passwordless `sudo` for the chroot build. The installed-system update path
  is unchanged from `v1.03`.
- No `.asc` signature is published: no GPG signing key is available. Verify
  the source tag against the commit and verify any ISO with `SHA256SUMS.txt`.
