# 🚀 WebOS 1.034 "Ashen" — refreshed ISO, 6.12.119 + final glass fixes

This is a **new ISO release** that supersedes the `v1.03` medium. It folds the
source-only kernel and boot-chain work from `v1.03.1`, `v1.03.2` and `v1.03.3`
into a clean image, together with everything committed to `main` since — most
notably the scoped Discord/Spotify transparency fixes. Existing 1.03 systems
receive the same rice/tree with a single `sudo webos-update`; no reinstall is
required. Fresh installs additionally ship automatic clock sync via chrony.

Like 1.03, this image is built from a fresh Gentoo stage3 chroot populated only
from this repository — not from a maintainer's installed system — so none of the
build host's accounts, browser profiles, game saves, SSH keys or local overrides
end up on the medium.

> **Base:** Gentoo · OpenRC + elogind · no systemd
> **Kernel:** `6.12.119-webos` LTS + WebOS tuning
> **Desktop:** Hyprland + the Ashen mono rice
> **Installer:** `webos-installer` 1.0.0
> **Theme:** `webos-theme-1.0-r52`

## 🐛 Fixed since 1.03

- **Kernel security update:** the image ships Linux 6.12.119 LTS (with the
  current stable patch) instead of 6.12.0, and no longer carries the broken
  ebuilds from `v1.03.1`.
- **Unbootable kernel fallback:** `webos-update` and the image build now prepare
  `/usr/src/linux-6.12`, regenerate `Module.symvers`, repair the `/lib/modules`
  build symlink, rebuild NVIDIA from source with `KERNEL_DIR=...` (never a
  cached binpkg), run `depmod`, regenerate the initramfs for the exact kernel
  release and verify it contains the module tree before setting GRUB default.
- **Oversized picker backgrounds:** the global popout rule was painting Discord's
  large positioning wrapper. Wrapper layers are transparent now; only the
  innermost emoji/GIF/sticker/submenu container paints the dark glass.
- **Missing speaking ring:** a second, higher-specificity rule was restoring a
  green outline after the scoped override. Both rules now agree on blue, and
  the outline is applied to the avatar only — never the whole voice row. Volume
  bars remain visible white.
- **Red @mention row never appeared:** the selector contained
  `:not([class*="mention"])`, which also excluded the `mentioned` message class
  itself. It now matches `[class*="message"][class*="mentioned"]` directly.
- **Grey song text:** Spotify's compact widget and right-side now-playing
  caption use hashed classes and native `textSubdued` tokens outside
  `.main-trackInfo-*`. Those text leaves are explicitly white now.
- **Spotify text mask:** `--spice-sidebar` was set to `transparent`, which is
  also the solid stop in Spotify's text-fade masks; that erased the writing.
  It is opaque now while the window surfaces stay transparent.
- **Discord controls:** white buttons, dimmed composer placeholder, white GIF
  icon with black lettering on a transparent plate, white Add Server `+` on its
  plate, white server-selected dot and white notification circles.
- **Discord popouts and indicators:** profile/account menus have a faint grey
  plate, the selected expression-picker tab has its own subtle pill, and server
  unread dots, channel unread pills and notification badges are solid white.
- **Clock and region defaults:** the old image always booted UTC with a `us`
  keymap and no time daemon. `chronyd` now runs on the live medium and the
  installed system; the Region page detects timezone (local zone → IP
  geolocation → UTC) and suggests a keymap, with `r` re-detection in both UIs.
- **Update pill and BSC:** the idle update pill stays hidden until an update is
  available; one click still updates Discord, Flatpaks and the whole system.
  The BetterSoundCloud artist fix is synced.
- **Branding:** old product naming is gone from shipped files and docs; the only
  remaining strings are build-time cleanup selectors that never enter the ISO.
- **Long-standing desktop items retained:** Hyprland 0.57 remains on a Lua config
  (`hyprland.lua` + `webos-colors.lua`); SDDM shows only the chosen session;
  clickable workspaces, Super+scroll 1–5, Super+Escape lock and 170 Hz
  persistence are unchanged.
- **FFlags scope:** Roblox/Sober FFlags stay allowlisted to those apps. No
  system-wide FPS tweaks, and local Sober config is not synced.

## 📦 Assets

GitHub limits single release files to 2 GB, so the full ISO is published as
split parts:

- `webos-1.034-Ashen-amd64.iso.part-00`, `-01`, … (reassemble with `cat`)
- `README.txt`, `SHA256SUMS.txt`
- `webos-1.034-Ashen-amd64.iso.b2` (BLAKE2b of the reassembled ISO)

Reassemble and verify on **Linux / macOS**:

```bash
cat webos-1.034-Ashen-amd64.iso.part-* > webos-1.034-Ashen-amd64.iso
sha256sum -c SHA256SUMS.txt
```

Reassemble on **Windows** (PowerShell or CMD):

```bat
copy /b webos-1.034-Ashen-amd64.iso.part-* webos-1.034-Ashen-amd64.iso
```

Then verify the reassembled file with `certutil -hashfile
webos-1.034-Ashen-amd64.iso SHA256` and compare it with `SHA256SUMS.txt`.

Flash with Ventoy, Rufus, balenaEtcher or `dd`, boot the live medium, then run
`webos-installer`. See the [complete guide](../WEBOS-COMPLETE-GUIDE.txt) for
installer options and post-install setup.

## Validation

- `bash scripts/50-check.sh` reports **0 problems**, including the new
  v1.034 identity, asset-name and both reassembly-command checks.
- `cargo check --offline` passes and the region-detection unit tests pass 3/3.
- The build explicitly installs `net-misc/chrony` and fails unless `chronyd`,
  its OpenRC init script and `/etc/runlevels/default/chronyd` are present in
  the live rootfs; a candidate image missing them was rejected.
- `git diff --check` passes; Vencord Quick CSS, live Spicetify CSS and the
  patched Spotify CSS match their repository sources. The Spotify white-text
  fix was visually confirmed, including the bottom-left widget and the caption
  under the right-side artwork.
- The kernel/boot-chain checks from v1.03.3 remain in place: initramfs contains
  `nvidia.ko`, `nvidia_modeset.ko`, `nvidia_uvm.ko`, `nvidia_drm.ko` and the
  `620.73.04` firmware blobs.
- `uname -r` on the validated host reports `6.12.119-webos`.
