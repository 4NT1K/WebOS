# WebOS 1.022 (Ashen)

Fix release for the issues found in the 1.021 audit.

## Fixed

- **`webos-rice --doctor` false font failure.** The Inter / JetBrains Mono
  checks used `grep -q` under `set -o pipefail`. grep exited at the first
  match, `fc-list` died from SIGPIPE and the pipeline returned 141, so an
  installed font was reported missing. The checks now read the whole fc-list
  stream and fall back to `find ... -print -quit`.

- **Session services missing at login.** waybar, hypridle, hyprpaper, the
  portals and the polkit agent were only started by `exec-once` lines in
  `~/.config/hypr/hyprland.conf`. Homes themed by an older release kept a
  conf without those lines, so nothing started. `webos-session` now starts
  `webos-autostart` itself once the compositor answers. The helper is
  idempotent (it skips services that are already running) and uses a
  directory lock, so the `exec-once` copy is a harmless no-op.
  `/tmp/webos-autostart.log` and `/tmp/webos-portals.log` always record the
  attempt, including which polkit agent was chosen.

- **The upstream `hyprland.lua` example could still win.** Hyprland 0.57
  seeds `~/.config/hypr/hyprland.lua` from `/usr/share/hypr/hyprland.lua`
  and gives it precedence over `hyprland.conf`; that example has different
  keybinds (only Super+R appeared to work) and no WebOS autostart. The
  example is no longer shipped, `webos-rice --ensure` moves any existing lua
  aside at every login, and `--doctor` fails if an active one is present.

- **Hyprland config error mentioning `#`.** `webos-colors.conf` had inline
  `# ...` comments. hyprlang treats the rest of the line as part of the
  value, so the palette values were invalid and Hyprland reported a config
  error. All comments are on their own lines now.

- **SDDM config drift.** `10-webos.conf` no longer sets `DisplayServer`
  (Gentoo's `01gentoo.conf` selects the greeter backend; `DisplayServer` is
  about the greeter, not the user's Wayland session), and the installer no
  longer duplicates `DefaultSession`. The session chosen at install time is
  still seeded in `/var/lib/sddm/state.conf`.

## Assets

- `webos-1.022-Ashen-amd64.iso.part-00 … part-02` — split ISO
- `SHA256SUMS.txt` — checksums for the parts
- `README.txt` — reassembly instructions

Reassemble and verify:

```sh
cat webos-1.022-Ashen-amd64.iso.part-* > webos-1.022-Ashen-amd64.iso
sha256sum -c SHA256SUMS.txt
```

Write the ISO to a USB stick with Ventoy, Rufus, balenaEtcher or `dd`.
