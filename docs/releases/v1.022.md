# WebOS 1.022 (Ashen)

Fix release for the issues found in the 1.021 audit.

## Fixed

- **The Hyprland rice now actually loads.** Hyprland 0.57 reads Lua
  configuration (`~/.config/hypr/hyprland.lua`) and ignores `hyprland.conf`
  entirely. 1.021's fix moved the upstream lua aside and pinned
  `hyprland.conf`, so the compositor ran its built-in defaults: no keybinds,
  no autostart, no blur. The rice is now `hyprland.lua` plus a small
  `webos-colors.lua` palette module, validated with
  `Hyprland --verify-config`. `hyprland.conf` is gone.

- **`webos-rice` handles existing homes.** It replaces only the untouched
  upstream lua example (identified by its `This is an example Hyprland Lua
  config file.` header), removes its own old `hyprland.conf`, and leaves a
  config the user edited alone unless `--force` is used.

- **`webos-session` launches the right config.** Plain `Hyprland` finds
  `hyprland.lua` on its own, so the explicit `-c hyprland.conf` is gone.
  `--safe` still uses `-c /dev/null`. `webos-rice --doctor` now checks that
  `hyprland.lua` exists and is the WebOS config, and that `webos-colors.lua`
  is present.

- **`webos-rice --doctor` false font failure.** The Inter / JetBrains Mono
  checks used `grep -q` under `set -o pipefail`. grep exited at the first
  match, `fc-list` died from SIGPIPE and the pipeline returned 141, so an
  installed font was reported missing. The checks now read the whole fc-list
  stream and fall back to `find ... -print -quit`.

- **Session services missing at login.** waybar, hypridle, hyprpaper, the
  portals and the polkit agent are started by `webos-autostart`, which the
  Lua config starts on `hyprland.start` and `webos-session` also runs once the
  compositor answers. It uses a directory lock in `$XDG_RUNTIME_DIR`, skips
  services that are already running, and logs to `/tmp/webos-autostart.log`.
  `/tmp/webos-portals.log` always records the attempt, including which polkit
  agent was chosen.

- **Portal detection.** `webos-portals` used `pgrep -f xdg-desktop-portal`,
  which also matches the `-gtk` and `-hyprland` backends, so the script
  believed the portal it was about to start was already running. It now
  compares argv[0] exactly.

- **Lock screen had no logo.** `/usr/share/webos/logo.svg` was installed from
  `webos-wallpaper.svg`, a 3840x2160 black rectangle, so hyprlock drew an
  invisible black square. The real 512x512 mark is installed instead.

- **Night light.** hyprsunset was never started and used `gamma = 90`/`100`
  where the option is a multiplier (1.0 = 100%). It now starts with the
  session and the profiles use `gamma = 1.0`.

- **Idle handling.** hypridle's 60-second "don't sleep in a game" listener ran
  a `hyprctl`/`jq` pipeline that could not inhibit anything. Removed; hypridle
  honours the D-Bus idle inhibitor that games and video players already take.

- **`webos-rice --wallpaper`.** It called a `hyprctl keyword wallpaper` that
  does not exist. It now rewrites `hyprpaper.conf`, preloads the image over
  hyprpaper IPC and falls back to `swaybg`. The wallpaper menu uses `fzf`
  when present and `wofi` otherwise.

- **Pointer acceleration** stays off (`accel_profile = flat`,
  `force_no_accel = true`) in the Lua config.

- **SDDM config drift.** `10-webos.conf` no longer sets `DisplayServer`
  (Gentoo's `01gentoo.conf` selects the greeter backend; `DisplayServer` is
  about the greeter, not the user's Wayland session), and the installer no
  longer duplicates `DefaultSession`. The session chosen at install time is
  still seeded in `/var/lib/sddm/state.conf`.

- **The greeter offers the desktops that are installed.** The installer points
  SDDM at `/usr/share/webos/sessions` and links WebOS, Plasma and the gamescope
  session when their `.desktop` files exist, with the profile chosen in the
  installer as the default. 1.021 linked only the chosen session, so an
  installed Plasma could not be selected at login.

- **SDDM is the shipped greeter.** `webos-desktop` now depends on
  `gui-apps/sddm` instead of `greetd`/`tuigreet`, matching the
  `display-manager` configuration and `01gentoo.conf`. `webos-rice` still
  configures greetd only when greetd is actually the installed greeter.

- **Installer progress is honest.** A finished stage is checked off (and
  logged at 100%) before the next one starts; the bar only moves forward, and
  the panel shows `stage n/12` for the current one. `udevadm`, `partprobe`,
  `mount` and every other helper now run with null stdio, so their output can
  no longer paint over the TUI. rsync's own progress drives the bar during the
  copy.

- **The live banner follows the build.** It used to hard-code "1.021" and
  would have been wrong on every later ISO; it now reads `PRETTY_NAME` from
  `/etc/os-release`.

## Assets

- `webos-1.022-Ashen-amd64.iso.part-00 … part-02` — split ISO
- `SHA256SUMS.txt` — checksums for the parts
- `README.txt` — reassembly instructions

Reassemble and verify:

```sh
cat webos-1.022-Ashen-amd64.iso.part-* > webos-1.022-Ashen-amd64.iso
sha256sum -c SHA256SUMS.txt
```

Write the ISO to a USB stick with Ventoy, Rufus, balenaEtcher or `dd`.
