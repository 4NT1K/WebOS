# 🚀 WebOS 1.02 "Ashen"

The second maintenance rebuild of Ashen. It keeps the same look and feel as
1.01, fixes the issues found after release, and adds the new music dropdown,
power and session behaviour. Existing 1.01 systems receive these changes with
one `sudo webos-update`; no manual file copying is needed.

> **Base:** Gentoo · OpenRC + elogind · no systemd
> **Kernel:** `6.12.0-webos` LTS + WebOS tuning
> **Desktop:** Hyprland + the Ashen mono rice
> **Installer:** `webos-installer` 1.0.0
> **Theme:** `webos-theme-1.0-r49`

## 🧩 What changed

### Power, lock and session

- The mono Waybar profile now ends with `custom/power`: glyph `⏻`, tooltip
  `Power — open session menu (reboot, shut down, suspend)`, and `on-click: wlogout`.
- `webos-rice` migrates only the exact distro-generated legacy Waybar config,
  backs it up once as `.webos-orig`, and leaves genuinely user-edited
  files alone.
- Hyprlang needs `##` for a literal `#` in a value. The lock placeholder is now
  `foreground="##7A7A7A"`, so it no longer shows raw Pango markup.
- Obsolete `grace` and `no_fade_in` keys were removed from `hyprlock.conf`;
  hypridle now calls `hyprlock --grace 0 --no-fade-in`.
- Idle blanking uses the compositor's real Lua API:
  `hl.dispatch(hl.dsp.dpms({ action = "off" }))` / `"on"`.
- The dim listener is guarded by `/sys/class/backlight` and uses
  `brightnessctl -c backlight`, so it no longer changes keyboard LEDs.
- Waybar IPC is disabled in both rice and mono configs; the "socket path is
  empty" warning is gone.
- Power actions remain `loginctl`-only. No `systemctl` is used or assumed.

### Music player and dropdowns

- `webos-music` is a 340x340 GTK layer-shell card under the bar, namespace
  `webos-music`. It slides down from above the panel into a 100px top margin.
- Album art is cover-cropped to the square, lightly blurred with overscan and
  a 0.06 dark overlay. It fills the whole card background and becomes the
  centre label of the vinyl.
- The separate grey art strip is gone; the card uses the frosted cover itself.
- A Cairo-drawn vinyl spins in the middle while Spotify plays, with grooves,
  a fixed reflection and the cached cover as its centre label. cava and
  PipeWire capture are no longer used by the card.
- `art_is_light()` selects pure black or white text, buttons, progress and
  volume bars with no glow or outlines. Playback buttons sit below the progress
  bar; the slim volume fader is outline-free and Spotify-only.
- Both dropdowns try `GtkLayerShell-0.1.typelib` before `1.0` (WebOS ships 0.1),
  use a TOP-layer transparent catcher behind an OVERLAY-layer card, and clear
  stale Hyprland error overlays with `hyprctl seterror disable`.
- `webos-stats` keeps the detailed v1.01 data: RAM used/total and one row per
  CPU core with usage and temperature, e.g. `c0   2% 53C`.

### Updates and packages

- `webos-update` keeps `--getbinpkg` and the pinned Gentoo `x86-64-v3` binhost.
  It does **not** use `-G`, `-K` or `--binpkg-respect-use=n`, so stock binaries
  with the wrong USE flags are never forced onto the machine.
- New flags:
  - `--fast` / `--fast-binpkg` — accept binpkgs whose dependency metadata
    changed (`--binpkg-changed-deps=n`) while still requiring strict USE match.
  - `--strict-use` / `--respect-use` — explicitly require exact USE matching.
  - `--buildpkg` — cache any remaining source builds locally.
  - `--no-compile` — pre-flight the plan and abort before any changes if a
    source build would be required. It does not use `--getbinpkgonly`.
- The updater reports real binary/source counts; the Waybar badge
  (webos-update-indicator) counts both `[binary` and `[ebuild` lines and
  launches manual `webos-update` on click.

### Installer, build and docs

- The installer progress panel now counts 12 phases without encryption and 13
  with it, including the previously omitted "Installing the bootloader" phase.
- The Gaming toggle now removes gaming-only packages when off and writes
  `/etc/webos/gaming-not-installed.txt`; shared graphics packages stay.
- Steam wording describes the Flatpak Steam fallback instead of promising a
  native Steam/Proton install that this 64-bit-only image cannot provide.
- Manifest digests are hex BLAKE2B values, not base64.
- The kernel ebuild stamps `/boot/webos-fragment.sha256`; `20-kernel.sh`
  forces a rebuild when the stamp is missing or stale.
- Build scripts use `compgen -G` for ISO glob checks, watchers no longer use
  hard-coded foreign paths or auto-commit, and the status updater is opt-in via
  `WEBOS_STATUS_UPDATER=1`.
- `/usr/share/webos/WEBOS-INFO.txt` is updated in the image and documents the
  new workflow from WebOS itself.

## 🔄 Upgrading from 1.01

On the installed machine:

```sh
sudo webos-update
```

The `main` branch on GitHub has been updated with this release, so the updater
will find the new ebuilds. `webos-update` refreshes the WebOS overlay from
`main`, upgrades the theme to `webos-theme-1.0-r49`, updates @world, re-applies
the rice and reports what it did. Log out and back in (or reboot) once
afterwards so Hyprland, Waybar and the lock screen pick up the new files. No
manual `cp` is required.

If you only want to see the plan first:

```sh
sudo webos-update --check
```

## 💿 Download and install

Download the split assets for **`webos-1.02-Ashen-amd64.iso`**: `README.txt`,
`SHA256SUMS.txt`, and `webos-1.02-Ashen-amd64.iso.part-00` through
`webos-1.02-Ashen-amd64.iso.part-02`. Reassemble and verify them in order:

```sh
cat webos-1.02-Ashen-amd64.iso.part-00 \
    webos-1.02-Ashen-amd64.iso.part-01 \
    webos-1.02-Ashen-amd64.iso.part-02 > webos-1.02-Ashen-amd64.iso

sha256sum -c SHA256SUMS.txt
```

Flash the resulting ISO with Ventoy, Rufus, balenaEtcher or `dd`. UEFI is
recommended; BIOS is supported.

## 📌 Known notes

- Fastfetch logo art is chafa symbols only — no native image, kitty or
  sixel support; the text cobweb is the fallback.
- The music card needs `pycairo` and the `GtkLayerShell-0.1` typelib. The
  panel degrades gracefully if the cached cover is unavailable.
- 32-bit Wine and native Steam are still out of scope for this 64-bit-only
  image; use the Flatpak Steam fallback.
- Use plain `webos-rice --user`, not `--force`, on an existing install unless
  you intend to overwrite user-edited managed files.
- The machine is **not** shut down by the updater or by this release.
