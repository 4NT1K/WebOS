# WebOS 1.03.2 "Ashen" — corrected kernel security update

This release supersedes the broken `v1.03.1` kernel update.

| | |
|---|---|
| Installed identity | WebOS 1.03 (Ashen) — unchanged |
| Git tag | `v1.03.2` |
| Kernel | `6.12.119-webos` (Linux 6.12 LTS, 2026-11-23) |
| Delivery | WebOS overlay + `webos-update` |

## What broke in v1.03.1

`kernel-2.eclass` treats a three-component kernel version differently from a
two-component one. For `PV=6.12.119`, `detect_version()` sets `KERNEL_URI` to:

```
linux-6.12.tar.xz + patch-6.12.119.xz
```

and `universal_unpack()` always unpacks `linux-6.12.tar.xz`, then applies the
patch. The `v1.03.1` ebuilds instead pinned the combined
`linux-6.12.119.tar.xz`, so Portage never placed the expected base tarball in
`DISTDIR`. The sources ebuild failed in `src_unpack` with:

```
unpack: 'linux-6.12.tar.xz' either does not exist or is not a regular file
```

The kernel ebuild failed in the same emerge batch because its source-package
step could not complete. It was collateral from that one unpack error, not a
separate kernel compile failure.

## What changed in v1.03.2

- Both kernel ebuilds now use `SRC_URI="${KERNEL_URI}"` and let
  `kernel-2.eclass` supply the base tarball plus incremental patch.
- Both `Manifest` files pin `linux-6.12.tar.xz` and `patch-6.12.119.xz`.
- `scripts/50-check.sh` now asserts both ebuilds use `KERNEL_URI` and that both
  Manifests carry the base tarball and patch digests.
- Docs and release notes explain the three-component unpack rule.
- No ebuild revision bump was needed: the failed packages were never
  installed, so Portage will retry 6.12.119 from the refreshed overlay.

## Validation

- Verified `linux-6.12.tar.xz` matches its previously pinned digest.
- Verified `patch-6.12.119.xz` applies cleanly to the 6.12 tree and produces
  `SUBLEVEL = 119`.
- Verified the GCC 16 C11 workaround still matches the patched Makefiles.
- `bash -n`, `git diff --check`, and `bash scripts/50-check.sh` pass.
- No ISO was rebuilt or boot-tested here: this host has no passwordless
  `sudo` for the chroot build.

## How to update

```bash
sudo webos-update
sudo reboot
uname -r        # 6.12.119-webos
```

Old kernels remain in the GRUB menu as a fallback. If the update still fails,
attach `/var/log/webos-update.log` and the Portage build log for
`sys-kernel/webos-kernel-sources-6.12.119`.
