WebOS 1.01 "Ashen" — fix log for the replacement image
=========================================================

This file records defects found during the post-release audit and exactly how
each one was fixed in the source tree so a fresh install does not reproduce
them. It is intended to travel with the replacement v1.01 ISO assets.


[1] Power button missing from the top-right bar
------------------------------------------------
Symptom:
  Fresh installs seeded from the "mono" dotfiles profile had no far-right
  power pill, even though /usr/share/webos/rice/waybar/config.jsonc had one.

Cause:
  The installer copies ~/.config/waybar from
  overlay/webos-theme/files/dotfiles/mono/waybar/, but that profile had a
  config with `modules-right` ending at custom/perf. webos-rice only manages
  files whose current hash matches its manifest, so user copies were left
  alone on update.

Fix:
  - Copied the power-enabled rice config/style into the mono dotfiles profile.
  - Added migrate_legacy_waybar() to webos-rice. It upgrades only the exact
    known distro-generated hash of the old mono config/style, backs up the
    old file once, and records the new hash. Genuinely user-edited files are
    left untouched.
  - Bumped webos-theme to 1.0-r2 and pinned scripts/30-rootfs.sh to it.
  - Added scripts/50-check.sh assertions for the mono power widget.


[2] Lock screen showed raw "span foreground" text
--------------------------------------------------
Symptom:
  The password field displayed the beginning of Pango markup instead of a dim
  "enter password..." hint. Runtime log:
    Updating placeholder text: <span foreground="

Cause:
  Hyprlang treats a single `#` as a comment marker even inside a value. With
  `foreground="#7A7A7A"` the parser truncated the value at `#`, Pango could
  not parse the incomplete markup, and rendered the raw text. Hyprlang
  escapes a literal `#` as `##`.

Fix:
  - Changed the rice hyprlock placeholder to foreground="##7A7A7A".
  - Corrected the webos-rice --doctor check: it now requires an escaped
    six-digit hex colour instead of rejecting any `##`.
  - Added a scripts/50-check.sh assertion for the escaped colour.


[3] hyprlock rejected two config options on every lock
-------------------------------------------------------
Symptom:
  /tmp/webos-autostart.log repeatedly showed:
    config option <general:grace> does not exist.
    config option <general:no_fade_in> does not exist.

Cause:
  Hyprlock 0.9.7 no longer accepts these as config-file entries. They are CLI
  flags (`--grace`, `--no-fade-in`).

Fix:
  - Removed general.grace and general.no_fade_in from the rice hyprlock.conf.
  - Changed hypridle lock_cmd to:
      pidof hyprlock || hyprlock --grace 0 --no-fade-in
  - Added doctor/check-script assertions that the removed options are absent
    and the flags are present.


[4] Idle display blank did nothing
----------------------------------
Symptom:
  After 10 minutes, hypridle logged:
    error: [string "return hl.dispatch(dpms off)"]:1: ')' expected near 'off'
  and the screen never blanked.

Cause:
  Hyprland 0.57 with a Lua config translates `hyprctl dispatch <args>` into
  `hl.dispatch(<args>)`. The old `dpms off` tokens are not valid Lua.

Fix:
  - Replaced the hypridle DPMS commands with:
      hyprctl eval 'hl.dispatch(hl.dsp.dpms({ action = "off" }))'
      hyprctl eval 'hl.dispatch(hl.dsp.dpms({ action = "on" }))'
  - Verified the "on" form returns `ok` on the live session.
  - Added check-script assertions and a doctor check for the new syntax.


[5] Idle "dim" changed keyboard LEDs, not the display
-----------------------------------------------------
Symptom:
  The 2.5-minute dim rule logged changes to input2::numlock and other LED
  devices. There is no /sys/class/backlight on this desktop.

Cause:
  `brightnessctl -s set 15%` saves state and sets every brightness device,
  including /sys/class/leds. `-s` is save, not selective.

Fix:
  - Scoped the command to the backlight class and guarded it:
      find /sys/class/backlight -mindepth 1 -maxdepth 1 -print -quit |
        grep -q . && brightnessctl -c backlight -s set 15%
  - The resume command is guarded the same way and restores only backlights.
  - Added a check-script assertion for `-c backlight`.


[6] Waybar logged an IPC warning on every launch
-------------------------------------------------
Symptom:
  config.jsonc had "ipc": true but no socket path, so Waybar logged
  "Failed to open bar ipc connection: Socket path is empty".

Cause:
  The rice does not use Waybar IPC; webos-rice --toggle-panel uses pkill plus
  relaunch.

Fix:
  - Set "ipc": false in the rice and mono Waybar configs.
  - Added a check-script assertion.


[7] Slow updates compiled too much from source
----------------------------------------------
Symptom:
  `sudo webos-update` spent ~50 minutes compiling LLVM, Clang, FFmpeg and KDE
  frameworks, with load averages above 20.

Cause:
  WebOS uses custom USE flags and overlays. Gentoo's stock x86-64-v3 binhost
  builds packages with its own USE set, so Portage correctly rejected many
  binpkgs ("non matching USE" / "changed dependencies") and fell back to
  source. Packages from guru/hyprolay/webos overlays are never on that binhost.

Fix:
  - `EMERGE_DEFAULT_OPTS` in config/make.conf now includes
    `--binpkg-respect-use=n --binpkg-changed-deps=n`, so Portage no longer
    rejects stock binpkgs just because USE flags or dependency sets differ.
    A plain `emerge` is binary-first too, not only `webos-update`.
  - `webos-update` is binary-first by default. `--fast` / `--fast-binpkg` are
    kept as explicit aliases, and the new `--strict-use` / `--respect-use`
    flag restores the old behaviour for users who want WebOS USE flags honoured
    exactly. The updater prints a warning whenever stock binpkgs are accepted.
  - Added opt-in `webos-update --buildpkg`, which passes `--buildpkg` so the
    packages that still must be compiled are cached locally for future updates.
  - Overlay-only packages (guru/hyprolay/webos) still compile; there is no
    public binhost for them. Packages absent from the binhost snapshot also
    still fall back to source, but the USE/deps mismatch class is fixed.


[8] Music dropdown: frosted art in the middle of the screen
------------------------------------------------------------
Symptom:
  The dropdown appeared centred on the desktop instead of dropping down under
  the bar. The cover art was flattened to dark greyscale instead of filling the
  player as a lightly frosted, recognisable background, and the panel was a
  wide rectangle rather than a square.

Cause:
  - prepare_art() converted every cover to greyscale and dimmed it, discarding
    the colour information entirely.
  - The art was a small 640x280 strip at the top of a 640x440 card instead of
    the whole player background.
  - gui-libs/gtk-layer-shell was installed without its `introspection` USE
    flag, so the Python GtkLayerShell typelib was missing. webos-music silently
    fell back to an ordinary floating window, which Hyprland centred on screen
    and decorated with the global blur.

Fix:
  - prepare_art() now cover-crops the album art to a 340x340 square, applies a
    modest radius-9 blur (with overscan cropping to avoid soft edges), and
    dims it only to 0.72 so the artwork stays easy to recognise. This single
    image is applied as the `#music-card` CSS background with `cover` sizing,
    so the song image fills the entire player.
  - Removed the separate image widget and old 640x280 art box. Status, title,
    artist, an audio visualizer, transport buttons and seek bar sit over the
    frosted image.
  - Added a cava-driven audio visualizer in the middle of the panel. It resolves
    the active MPRIS player to its own PipeWire node via `pw-dump`, then runs
    `cava` against that node alone (`[input] method = pipewire, source = <node>`)
    with raw ASCII output, so notifications, browser tabs and other system
    audio are never visualised and the motion inherits cava's own smoothing.
    A light extra attack/decay filter removes stray frames. The 20 bars are
    drawn with rounded tops and a vertical brightness gradient on a
    Gtk.DrawingArea; their colours are sampled from the current cover art
    (quantised with Pillow) so the visualizer follows the song's colour scheme.
    Capture only runs while the panel is visible and follows the player if it
    changes.
  - The window and card are now a compact 340x340 square. Showing the panel
    animates it downward from above the bar into place (eased GLib timeout
    that moves the layer-shell margin, or the fallback window via hyprctl),
    with a short retry so Hyprland focuses the window first.
  - Gave the layer-shell window the namespace `webos-music`.
  - Both `webos-music` and `webos-stats` now show a transparent fullscreen
    click-catcher behind the card while the dropdown is open. Clicking
    anywhere outside the card dismisses it; the card itself keeps its own
    controls. The dropdown sits on the OVERLAY layer so it stays above the
    catcher.
  - Added a Hyprland window rule for class `webos-music` with `float = true`
    and `no_blur = true`, so the compositor does not double-blur the card.
  - Bumped webos-theme to 1.0-r3 and made it depend on
    `gui-libs/gtk-layer-shell[introspection]` so fresh installs and
    `webos-update` get the typelib that makes the native layer-shell path work.
  - Pinned scripts/30-rootfs.sh to r3 so the patched ISO ships these files.


[9] Installer, overlay and build-tooling audit fixes
-----------------------------------------------------
A repository-wide audit found several smaller but real defects. They were
fixed without changing the installed desktop behaviour:

- Installer stage counter: added the missing "Installing the bootloader" phase
  and corrected the phase order so the progress denominator matches the phases
  actually emitted (12 with encryption off, 13 with it on).
- Gaming toggle: the wizard's Gaming switch was inert. Turning it off now
  removes the gaming-only packages baked into the live image and records a
  note in /etc/webos/gaming-not-installed.txt. Shared graphics packages stay.
- Steam wording: the UI no longer promises a Steam install. The toggle is
  labelled as a 64-bit note, the summary says steam=note/off, and profile notes
  now mention the Flatpak Steam fallback instead of Steam/Proton.
- Gentoo Manifests: base64 BLAKE2B values on EBUILD/MISC lines were replaced
  with the hex digests the repo's own mkmanifest.sh and Portage expect.
- Kernel fragment tracking: the kernel ebuild now stamps the fragment SHA256 in
  /boot/webos-fragment.sha256, and scripts/20-kernel.sh forces a rebuild when
  that stamp is missing or stale. This replaces the fragile single-option grep.
- setup-container-build.sh: replaced the invalid `[[ -f build/webos-*.iso ]]`
  glob test with `compgen -G`.
- Watcher utilities: the private watchers no longer use hard-coded
  /home/brah/sanusos or /sanusos paths, no longer auto-commit/push tracked
  docs, and status-updater.sh is opt-in via WEBOS_STATUS_UPDATER=1.
- Documentation/branding: corrected stale binhost/overlay/ARM/version/NVIDIA/
  ISO claims, repaired truncated architecture prose, updated audit snapshots,
  changed os-release ANSI_COLOR to a greyscale value, and updated stale
  package metadata/maintenance instructions.

[10] Audit coverage
-------------------
Added scripts/50-check.sh assertions for all of the above so a rebuilt image
fails fast if any fix is regressed. WEBOS_ROOT=/path/to/WebOS bash
scripts/50-check.sh reports 0 problem(s) with these fixes applied.

[11] Mass recompilation during updates
---------------------------------------
Symptom:
  `sudo webos-update` rebuilt ~95 packages from source and failed on
  nvidia-drivers and webkit-gtk; Portage's "!!!" binpkg USE/dependency warnings
  were mistaken for the cause.

Cause:
  The shipped make.conf and updater accepted a binary only when its USE flags
  and dependency set matched exactly. WebOS uses ~amd64 and custom flags, so
  almost every update fell back to source.

Fix:
  EMERGE_DEFAULT_OPTS and webos-update now pass
  --binpkg-respect-use=n --binpkg-changed-deps=n (binary-first). A dry run of
  @world dropped from 235 source builds to 5. `--strict-use` restores exact
  matching, `--fast` is an alias for the default, `--buildpkg` caches the few
  remaining builds, and the new `--no-compile` flag pre-flights the dry run and
  aborts when any source build is required (it deliberately avoids
  --getbinpkgonly, which would reinstall 815 packages). Docs updated.

[12] Empty dropdown windows and top error overlay
-------------------------------------------------
Symptom:
  Opening the music player left an empty box below it; opening the performance
  stats opened a second empty window. A red Hyprland error bar sat at the top of
  the screen.

Cause:
  Both scripts requested the GtkLayerShell 1.0 GObject namespace, but WebOS
  ships GtkLayerShell-0.1.typelib. The failed import silently disabled
  layer-shell, so the transparent fullscreen click-catcher fell back to a bare
  200x200 toplevel. The red bar was Hyprland's persistent error overlay.

Fix:
  Both scripts try GtkLayerShell 0.1 before 1.0; the catcher is now a proper TOP
  layer and the card an OVERLAY layer, so no extra window is visible. Both
  panels use a 100px top margin so they sit below the top bar (stats aligned
  to the top right). The stale error overlay is cleared with
  `hyprctl seterror disable`. Regression checks added.
